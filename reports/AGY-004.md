# Báo cáo nghiệm thu AGY-004: Xử lý exit code + event result → SUCCESS / ERROR / INVALID_OUTPUT — Test 3 trường hợp

## 1. Mục tiêu và Tiêu chí nghiệm thu
- **Nhiệm vụ theo ROADMAP.md**:
  - Triển khai bộ phân giải trạng thái lần chạy (`resolveRunStatus`) dựa trên mã thoát tiến trình (`exitCode`), tín hiệu ngắt (`signal`) và các sự kiện luồng stream (`events`), đặc biệt là sự kiện `result`:
    - `exit 0 + có event result hợp lệ` → `SUCCESS` (ghi nhận CLI hoàn tất thành công; lưu ý phân biệt CLI thành công với task DONE).
    - `exit ≠ 0 hoặc event result báo lỗi` → `ERROR` (xử lý mã lỗi hệ điều hành khác 0 hoặc event result mang `status: 'ERROR'`, `status: 'FAILED'`, `success: false`).
    - `exit 0 nhưng không có/sai result` → `INVALID_OUTPUT` (xử lý trường hợp process kết thúc bình thường nhưng output rỗng, thiếu event `result`, cú pháp JSON bị hỏng, hoặc payload không hợp lệ theo Zod schema).
    - Hỗ trợ các trạng thái vòng đời mở rộng: `TIMEOUT` khi tiến trình bị hủy do vượt quá thời hạn cho phép và `CANCELLED` khi người dùng chủ động dừng tiến trình.
  - Tích hợp vào `ExecutionStreamRecorder`: tự động gọi `resolveRunStatus()` khi tiến trình phát tín hiệu `close`, cập nhật trực tiếp trạng thái chuẩn hóa vào bảng `runs` trong cơ sở dữ liệu SQLite, và trả về thông tin `resolution` qua promise hoàn tất `waitForCompletion()`.
- **Tiêu chí nghiệm thu theo ROADMAP.md**: `Test 3 trường hợp` (SUCCESS / ERROR / INVALID_OUTPUT).

### Tiêu chí 1: Trường hợp 1 — SUCCESS (exit 0 + có event result hợp lệ)
- [x] **Nghiệm thu 1.1: Exit code 0 và event result mang status: "SUCCESS"**
  - *Mô tả*: Tiến trình con chạy kịch bản in các bước trung gian và in ra sự kiện `{"type": "result", "status": "SUCCESS", "summary": "All compilation targets built successfully"}` rồi thoát với exit code 0. Hệ thống bóc tách đúng sự kiện `result`, xác thực schema hợp lệ, gán trạng thái `SUCCESS` và cập nhật bản ghi trong bảng `runs` của SQLite.
  - *Bằng chứng*:
    - `test/agy-004.test.ts` ("1.1: xác nhận status SUCCESS khi exit 0 và event result có status 'SUCCESS'")
    - `packages/shared/src/__tests__/result.test.ts` ("resolves to SUCCESS when exit code is 0 and event result has status SUCCESS")
    - `apps/orchestrator/src/__tests__/execution-stream.test.ts` ("sets run status to SUCCESS when process exits 0 with a valid SUCCESS result event")

- [x] **Nghiệm thu 1.2: Exit code 0 và event result mang success: true**
  - *Mô tả*: Event result mang thuộc tính boolean `{"type": "result", "success": true, "data": { "filesModified": 3 }}`. Hệ thống nhận diện đây là kết quả thành công và gán trạng thái `SUCCESS`.
  - *Bằng chứng*:
    - `test/agy-004.test.ts` ("1.2: xác nhận status SUCCESS khi exit 0 và event result có success: true")
    - `packages/shared/src/__tests__/result.test.ts` ("resolves to SUCCESS when exit code is 0 and event result has success: true")

- [x] **Nghiệm thu 1.3: Chuẩn hóa không phân biệt hoa thường status: "success"**
  - *Mô tả*: Khi worker phát ra `status: "success"` (chữ thường hoặc có khoảng trắng thừa), bộ tiền xử lý `AgentResultStatusSchema` tự động trim và chuyển hoa thành `SUCCESS`.
  - *Bằng chứng*:
    - `test/agy-004.test.ts` ("1.3: xác nhận status SUCCESS khi status là chữ thường 'success' (chuẩn hóa tự động)")

- [x] **Nghiệm thu 1.4: Phân biệt CLI thành công (run SUCCESS) với đạt acceptance criteria (task chưa DONE)**
  - *Mô tả*: Tuân thủ mục 121 của `ROADMAP.md` và `SKILL-process-ndjson.md`: Trạng thái của phiên chạy trong bảng `runs` được cập nhật thành `SUCCESS` (xác nhận tiến trình CLI kết thúc tốt), nhưng trạng thái task trong bảng `tasks` vẫn giữ nguyên là `TODO`/`RUNNING` (chỉ chuyển `DONE` sau khi qua Quality Gate / Reviewer ở GĐ 3 và GĐ 4).
  - *Bằng chứng*:

### Tiêu chí 2: Trường hợp 2 — ERROR (exit ≠ 0 hoặc event result báo lỗi)

    - `apps/orchestrator/src/__tests__/execution-stream.test.ts` ("sets run status to ERROR when process exits with non-zero exit code")

- [x] **Nghiệm thu 2.2: Exit code khác 0 (exit 2) dù trước đó đã in event result SUCCESS**
  - *Mô tả*: Tiến trình đã in `result SUCCESS` nhưng ngay sau đó gặp lỗi crash và thoát với exit 2. Hệ thống ưu tiên mã thoát thực tế của hệ điều hành, bỏ qua cờ thành công trước đó và đánh dấu lần chạy là `ERROR`.
  - *Bằng chứng*:

- [x] **Nghiệm thu 2.3: Exit code 0 nhưng event result báo status: "ERROR"**
  - *Mô tả*: Tiến trình CLI hoàn tất với exit code 0 nhưng nội dung event result thông báo lỗi logic nghiệp vụ `{"type": "result", "status": "ERROR", "message": "Typecheck failed on src/index.ts"}`. Hệ thống ghi nhận trạng thái `ERROR` và trích xuất đúng thông điệp lỗi trong `reason`.

  - *Bằng chứng*:

### Tiêu chí 3: Trường hợp 3 — INVALID_OUTPUT (exit 0 nhưng không có/sai result)
- [x] **Nghiệm thu 3.1: Exit code 0 nhưng stream output hoàn toàn rỗng**
  - *Mô tả*: Tiến trình thoát exit 0 mà không ghi bất kỳ byte nào ra stdout/stderr. Do không có sự kiện `result`, hệ thống từ chối coi là thành công và gán trạng thái `INVALID_OUTPUT`.
  - *Bằng chứng*:
    - `test/agy-004.test.ts` ("3.1: xác nhận status INVALID_OUTPUT khi exit 0 nhưng không có output nào (empty output)")
    - `packages/shared/src/__tests__/result.test.ts` ("resolves to INVALID_OUTPUT when exit code is 0 but no events at all")

- [x] **Nghiệm thu 3.2: Exit code 0 nhưng chỉ in văn bản thô, không có event result**
  - *Mô tả*: Tiến trình in các dòng log thông thường (`console.log(...)`) rồi thoát exit 0 mà không hề phát ra event `result`. Hệ thống đánh dấu `INVALID_OUTPUT` với lý do `Process completed with exit code 0 but emitted no result event`.
  - *Bằng chứng*:
    - `test/agy-004.test.ts` ("3.2: xác nhận status INVALID_OUTPUT khi exit 0 nhưng chỉ in log văn bản thô không có event result")
    - `packages/shared/src/__tests__/result.test.ts` ("resolves to INVALID_OUTPUT when exit code is 0 with stdout/stderr but no result event")
    - `apps/orchestrator/src/__tests__/execution-stream.test.ts` ("sets run status to INVALID_OUTPUT when process exits 0 without emitting any result event")

- [x] **Nghiệm thu 3.3: Dòng event result bị lỗi cú pháp JSON (dẫn đến parse_error)**
  - *Mô tả*: Dòng NDJSON chứa sự kiện kết quả bị cắt cụt cú pháp (`{"type": "result", "status": "SUCCESS", "incomplete": `). `NdjsonParser` ghi nhận sự kiện `parse_error` và không tạo ra event `result` hợp lệ, dẫn đến run status được gán chuẩn xác là `INVALID_OUTPUT`.
  - *Bằng chứng*:
    - `test/agy-004.test.ts` ("3.3: xác nhận status INVALID_OUTPUT khi dòng result bị lỗi cú pháp JSON (parse_error)")

- [x] **Nghiệm thu 3.4: Event result thiếu cả 2 trường bắt buộc status và success**
  - *Mô tả*: Sự kiện có `type: "result"` nhưng payload chỉ chứa dữ liệu tùy ý (`{"type": "result", "summary": "...", "metadata": {}}`) mà không thông báo kết quả. Bộ kiểm định Zod từ chối payload và hệ thống đánh dấu `INVALID_OUTPUT`.
  - *Bằng chứng*:
    - `test/agy-004.test.ts` ("3.4: xác nhận status INVALID_OUTPUT khi event result thiếu cả 2 trường status và success")
    - `packages/shared/src/__tests__/result.test.ts` ("resolves to INVALID_OUTPUT when result event payload is missing required status or success")

- [x] **Nghiệm thu 3.5: Event result có giá trị status không hợp lệ**
  - *Mô tả*: Sự kiện mang giá trị status lạ (`{"type": "result", "status": "COMPLETED_UNOFFICIAL"}`). Zod schema validation thất bại và hệ thống chuyển thành `INVALID_OUTPUT`.
  - *Bằng chứng*:
    - `test/agy-004.test.ts` ("3.5: xác nhận status INVALID_OUTPUT khi event result có status không hợp lệ")
    - `packages/shared/src/__tests__/result.test.ts` ("resolves to INVALID_OUTPUT when result event has an unknown/invalid status string")
    - `apps/orchestrator/src/__tests__/execution-stream.test.ts` ("sets run status to INVALID_OUTPUT when result event payload is malformed/invalid schema")

- [x] **Nghiệm thu 3.6: Payload của event result không phải là JSON object**
  - *Mô tả*: Sự kiện mang payload là chuỗi, số hoặc `null`. Hệ thống đánh dấu `INVALID_OUTPUT`.
  - *Bằng chứng*:
    - `test/agy-004.test.ts` ("3.6: xác nhận status INVALID_OUTPUT qua resolveRunStatus khi payload của event result là null hoặc chuỗi")
    - `packages/shared/src/__tests__/result.test.ts` ("resolves to INVALID_OUTPUT when result event is null / not an object")
