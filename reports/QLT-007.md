## 1. Kết Quả Thực Hiện

### 1.1. Data Model & Zod Schemas (`packages/shared/src/models/quality-gate.ts`)
- **`QualityGatePolicySchema` & `QualityGateStatusSchema`**:
  - `QualityGateStatus`: `PASSED` | `FAILED`.
  - `QualityGateRuleStatus`: `PASSED` | `FAILED` | `SKIPPED` | `WARNING`.
  - Chính sách Quality Gate tổng thể chuẩn hóa từ `SKILL-testing.md`:
    - `requireFormatLintTypecheck`: bắt buộc format/lint/typecheck exit code 0.
    - `requireTest`: bắt buộc unit test exit code 0.
    - `requireBuild`: bắt buộc build exit code 0 (nếu có/được cấu hình).
    - `requireCleanScope`: không có file lạ ngoài phạm vi task (trừ khi nằm trong `allowedOutOfScopeFiles`).
    - `requireReviewClean`: không có finding `high` hoặc `critical` từ Reviewer Agent.
    - `requireNoSecrets`: không phát hiện secret / credential / private key chưa che giấu.
    - `requireAuditClean`: không có lỗ hổng phụ thuộc mức `high` hoặc `critical` từ `pnpm audit`.
    - `rejectCliSuccessOnly`: **ngăn chặn tuyệt đối việc đánh dấu task PASS chỉ vì CLI tiến trình báo SUCCESS / exit code 0 mà không có bằng chứng kiểm định thực tế**.
- **`QualityGateRuleEvaluationSchema` & `QualityGateEvidenceSummarySchema`**:
  - Đánh giá từng rule độc lập (`rule_id`, `name`, `stage`, `passed`, `status`, `message`, `details`).
  - Bóc tách tổng hợp bằng chứng đa chiều: CLI exit code & status, tổng số lệnh chạy, số lệnh pass/fail/skipped, số file ngoài scope, số findings review (phân loại high/critical), số secret findings, số lỗ hổng audit high/critical.
- **`QualityGateResultSchema`**:
  - Bản ghi kết quả đầy đủ: `id`, `task_id`, `run_id`, `repo_path`, `passed`, `status`, `summary`, `policy`, `rule_evaluations`, `evidence_summary`, `command_records`, `scope_result`, `review_result`, `security_result`, `duration_ms`, `evaluated_at`.
- **Helpers**:
  - `evaluateQualityGate(policy, evidence, options)`: Thực thi logic kiểm định nghiêm ngặt, tính toán PASS/FAIL từ bằng chứng thực tế, sinh thông điệp chi tiết.
  - `formatQualityGateMarkdownReport(result)`: Định dạng báo cáo kiểm toán Markdown chuẩn GitHub Flavored Markdown kèm bảng lệnh, kết quả exit code, thời gian thực thi, chi tiết vi phạm.

### 1.2. Migration 011 & SQLite Repository (`packages/db/migrations/011_quality_gates.sql`)
- Khởi tạo bảng `quality_gate_evaluations`:
  - Các cột: `id`, `task_id`, `run_id`, `passed`, `status`, `summary`, `policy_json`, `evaluations_json`, `evidence_summary_json`, `evidence_json`, `duration_ms`, `evaluated_at`, `created_at`.
  - Khóa ngoại liên kết `tasks(id)` và `runs(id)` với `ON DELETE CASCADE`.
  - Chỉ mục tối ưu: `idx_quality_gate_task_id`, `idx_quality_gate_run_id`, `idx_quality_gate_passed`, `idx_quality_gate_created_at`.
- **`QualityGateRepository` (`packages/db/src/repositories/quality-gate-repository.ts`)**:
  - `create(result)`: Lưu trữ bản ghi đánh giá Quality Gate an toàn trong SQLite transaction.
  - Tự động tạo bản ghi báo cáo kiểm toán trong bảng `reports` (`kind: 'quality_gate'`) khi có `run_id`.
  - `getById`, `findLatestByTaskId`, `findByTaskId`, `findByRunId`, `count`, `delete`.

### 1.3. Quality Gate Service (`apps/orchestrator/src/services/quality-gate-service.ts`)
- **`QualityGateService`**:
  - Tích hợp toàn diện 5 mô-đun Quality Gate:
    1. Cấu hình kiểm định `QualityConfigService` (QLT-001)
    2. Runner lệnh kiểm định `QualityRunner` (QLT-002)
    3. Kiểm soát diff và phạm vi `ScopeDiffService` (QLT-003)
    4. Đánh giá mã nguồn `ReviewerService` (QLT-004)
    5. Quét bảo mật và audit `SecurityCheckService` (QLT-005)
  - `runQualityGateForTask(taskId, options)`:
    - Thu thập trạng thái CLI của run gần nhất.
    - Chạy chuỗi lệnh kiểm định, phân tích git diff scope, gọi Reviewer Agent và quét Security.
    - Đánh giá Quality Gate từ bằng chứng thu thập được và lưu SQLite.
  - `verifyAndTransitionTask(taskId, options)`:
    - Đưa task sang `VERIFYING` khi kết thúc quá trình chạy.
    - Kích hoạt Quality Gate.
    - Nếu PASS: Chuyển task sang `DONE` với lý do và bằng chứng rõ ràng.
    - Nếu FAILED: Chuyển task sang `FAILED`, ngăn chặn tuyệt đối việc hoàn thành khi không đạt tiêu chí.
- **Tích hợp `TaskScheduler` (`apps/orchestrator/src/services/task-scheduler.ts`)**:
  - Tự động ủy quyền bước xác thực cho `QualityGateService` khi có kết quả `runStatus === 'SUCCESS'`, triệt để tuân thủ rule AGENTS.md:
    *"Không đánh dấu task nghiệp vụ DONE trong scheduler chỉ vì tiến trình AGY thoát mã 0. Chỉ chuyển sang VERIFYING; DONE phải đến từ bước kiểm định (Quality Gate) có bằng chứng."*

### 1.4. REST API Endpoints (`apps/orchestrator/src/routes/quality.ts`)
- `POST /api/quality/gate/evaluate`: Đánh giá Quality Gate theo yêu cầu cho một task.
- `GET /api/quality/gate/:id`: Lấy chi tiết bản ghi đánh giá Quality Gate.
- `GET /api/quality/gate/tasks/:id/latest`: Lấy kết quả Quality Gate gần nhất của task.
- `GET /api/quality/gate/tasks/:id/history`: Lấy lịch sử các lần đánh giá Quality Gate của task.
- `POST /api/tasks/:id/verify`: Kích hoạt quy trình kiểm định Quality Gate và cập nhật trạng thái task.

## 2. Tiêu Chí Nghiệm Thu & Bằng Chứng

### Tiêu chí cốt lõi: Không PASS chỉ vì CLI báo SUCCESS
- [x] **Nghiệm thu 1: "Không PASS chỉ vì CLI báo SUCCESS" — Tiến trình AGY/CLI exit 0, nhưng lệnh test thất bại**
  - Khi CLI thoát mã 0 / `status: 'SUCCESS'` nhưng lệnh test thất bại (`exit_code: 1`), Quality Gate đánh dấu `FAILED` với thông điệp: `"Không PASS chỉ vì CLI báo SUCCESS"`, task chuyển trạng thái sang `FAILED`.
  - *Bằng chứng*: `test/qlt-007.test.ts` (Nghiệm thu 1) & `apps/orchestrator/src/__tests__/quality-gate-service.test.ts` (test 3).
- [x] **Nghiệm thu 2: "Không PASS chỉ vì CLI báo SUCCESS" — CLI exit code 0 nhưng phát hiện file ngoài phạm vi (QLT-003)**
  - Dù CLI exit 0, nếu phát hiện file bị sửa đổi ngoài phạm vi cho phép, rule `SCOPE_COMPLIANCE` bị đánh dấu FAILED, task chuyển sang `FAILED`.
  - *Bằng chứng*: `test/qlt-007.test.ts` (Nghiệm thu 2) & `packages/shared/src/__tests__/quality-gate.test.ts` (test 4).
- [x] **Nghiệm thu 3: "Không PASS chỉ vì CLI báo SUCCESS" — CLI exit code 0 nhưng Reviewer Agent (QLT-004) phát hiện lỗi high/critical**
  - Dù các lệnh chạy thành công, nếu Reviewer Agent phát hiện lỗi nghiêm trọng mức `critical` hoặc `high`, rule `REVIEW_FINDINGS` bị đánh dấu FAILED, task chuyển sang `FAILED`.
  - *Bằng chứng*: `test/qlt-007.test.ts` (Nghiệm thu 3) & `packages/shared/src/__tests__/quality-gate.test.ts` (test 6).
- [x] **Nghiệm thu 4: "Không PASS chỉ vì CLI báo SUCCESS" — CLI exit code 0 nhưng phát hiện secret hoặc lỗ hổng audit (QLT-005)**
  - Dù CLI exit 0, nếu phát hiện credential/secret chưa che giấu hoặc phụ thuộc có lỗ hổng high+, Quality Gate bị đánh dấu FAILED, task chuyển sang `FAILED`.
  - *Bằng chứng*: `test/qlt-007.test.ts` (Nghiệm thu 4) & `packages/shared/src/__tests__/quality-gate.test.ts` (test 7, test 8).
- [x] **Nghiệm thu 5: "Không PASS chỉ vì CLI báo SUCCESS" — CLI exit code 0 nhưng không có bằng chứng kiểm định nào được thực thi**
  - Ngăn chặn triệt để việc "qua mặt" bằng cách bỏ qua mọi bước kiểm tra. Khi thiếu bằng chứng thực tế, rule `VERIFICATION_EVIDENCE_EXISTS` bị đánh dấu FAILED.
  - *Bằng chứng*: `test/qlt-007.test.ts` (Nghiệm thu 5) & `packages/shared/src/__tests__/quality-gate.test.ts` (test 2).
- [x] **Nghiệm thu 6: Đạt Quality Gate PASS khi mọi lệnh kiểm tra exit 0 và toàn bộ tiêu chuẩn được đáp ứng -> Task chuyển sang DONE**
  - Khi đầy đủ bằng chứng xác thực (lệnh test/lint exit 0, scope sạch, review không có lỗi high/critical, security sạch), Quality Gate đánh dấu `PASSED` và task chuyển sang `DONE`.
  - *Bằng chứng*: `test/qlt-007.test.ts` (Nghiệm thu 6) & `apps/orchestrator/src/__tests__/quality-gate-service.test.ts` (test 2).
- [x] **Nghiệm thu 7: Lưu vết toàn diện vào SQLite (quality_gate_evaluations và bảng reports)**
  - Lưu trữ chi tiết đánh giá vào bảng `quality_gate_evaluations` và sinh báo cáo kiểm toán markdown vào bảng `reports` (`kind: 'quality_gate'`). Hỗ trợ Cascade Delete khi xóa task.
  - *Bằng chứng*: `test/qlt-007.test.ts` (Nghiệm thu 7) & `packages/db/src/__tests__/quality-gate-repository.test.ts`.
- [x] **Nghiệm thu 8: REST API endpoints kiểm thử Quality Gate và kích hoạt xác thực cho task**

  - *Bằng chứng*: `test/qlt-007.test.ts` (Nghiệm thu 8).
