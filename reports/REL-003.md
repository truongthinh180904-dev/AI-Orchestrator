## 1. Kết Quả Thực Hiện

### 1.1. Data Models & Zod Schemas (`packages/shared/src/models/release.ts`)
- **`FeatureReleaseStatusSchema`**: Các trạng thái vòng đời release: `'BRANCH_CREATED' | 'COMMITTED' | 'PUSHED' | 'PR_CREATED' | 'READY_FOR_REVIEW' | 'MERGED' | 'CLOSED'`.
- **`FeatureReleaseSchema`**: Entity lưu trữ thông tin đợt phát hành: `id`, `feature_id`, `branch`, `base_branch`, `commit_sha`, `pr_url`, `status`, `metadata`, `created_at`, `updated_at`.
- **`CreateFeatureReleaseInputSchema`** & **`UpdateFeatureReleaseInputSchema`**: Hỗ trợ khởi tạo và cập nhật release record an toàn.
- **`CreateFeatureBranchInputSchema`**:
  - `branch_name`: Tùy chọn tên branch (mặc định: `feature/<feature-id>`).
  - `base_branch`: Tùy chọn base ref (mặc định tự động nhận diện: `main` -> `dev` -> `master` -> `HEAD`).
  - `repo_path`: Đường dẫn repo (mặc định: current dir `'.'`).
  - `require_clean`: Bắt buộc repo sạch trước khi tạo branch (mặc định: `true`).
  - `skip_readiness_check`: Bỏ qua kiểm tra release readiness (mặc định: `false`).
  - `checkout`: Chuyển sang branch vừa tạo (mặc định: `false`).
  - `check_remote`: Kiểm tra branch trên remote repository (mặc định: `false`).
- **`CreateFeatureBranchResultSchema`**: Trả về thông tin chi tiết: `release_id`, `feature_id`, `feature_name`, `branch`, `base_branch`, `commit_sha`, `created`, `status`, `repo_path`, `created_at`.
- **`FeatureBranchInfoSchema`**: Trả về thông tin trạng thái branch hiện tại và cờ `exists_locally`.

### 1.2. Git Utilities An Toàn (`packages/shared/src/git.ts`)
- **`validateGitBranchName(branchName)`**: Kiểm tra tên branch theo chuẩn `git check-ref-format` (từ chối chuỗi rỗng, khoảng trắng, ký tự đặc biệt `~^:?*[\`, dấu slash đầu/cuối, `..`, `//`, `@`, `@{`, đuôi `.lock`). Ném `AppError('INVALID_BRANCH_NAME')`.
- **`gitBranchExists(repoPath, branchName, options)`**: Kiểm tra sự tồn tại của branch qua `git show-ref --verify refs/heads/<branchName>` (và remote ref nếu cần).
- **`gitListBranches(repoPath, options)`**: Liệt kê các local / remote branches.
- **`gitGetCurrentBranch(repoPath)`**: Lấy branch hiện tại qua `git rev-parse --abbrev-ref HEAD`.
- **`gitGetRefCommit(repoPath, ref)`**: Trả về 40-ký tự commit SHA của ref (`git rev-parse --verify <ref>^{commit}`).
- **`gitGetDefaultBaseBranch(repoPath)`**: Tự động nhận diện base branch phù hợp (`main` -> `dev` -> `master` -> `HEAD`).
- **`gitCreateBranch(repoPath, options)`**:
  - Kiểm tra tính hợp lệ của tên branch (`validateGitBranchName`).
  - Kiểm tra trạng thái sạch của repo (`checkRepoClean`, ném `REPO_DIRTY` nếu bẩn).
  - Kiểm tra trùng branch (`gitBranchExists`): Nếu branch đã tồn tại, lập tức ném `AppError('BRANCH_ALREADY_EXISTS')`, tuyệt đối không dùng `-B` hoặc `--force` để ghi đè.
  - Xác nhận base branch tồn tại (`BASE_REF_NOT_FOUND`).
  - Tạo branch an toàn qua `runGitCommand(['branch', branchName, baseBranch], repoPath)`.
  - Hỗ trợ tùy chọn `checkout: true` qua `runGitCommand(['checkout', branchName], repoPath)`.
  - Thu thập SHA commit của branch vừa tạo.

### 1.3. Database Migration & FeatureReleaseRepository (`packages/db`)
- **Migration 012 (`packages/db/migrations/012_feature_releases.sql`)**:
  - Tạo bảng `feature_releases`: `id PRIMARY KEY`, `feature_id REFERENCES features(id) ON DELETE CASCADE`, `branch TEXT NOT NULL UNIQUE`, `base_branch TEXT NOT NULL`, `commit_sha TEXT`, `pr_url TEXT`, `status TEXT NOT NULL DEFAULT 'BRANCH_CREATED'`, `metadata_json TEXT`, `created_at TEXT`, `updated_at TEXT`.
  - Chỉ mục: `idx_feature_releases_feature_id`, `idx_feature_releases_branch`, `idx_feature_releases_status`.
- **`FeatureReleaseRepository` (`packages/db/src/repositories/feature-release-repository.ts`)**:
  - `create(input)`: Tạo bản ghi release, ném `AppError('BRANCH_ALREADY_EXISTS')` nếu vi phạm unique constraint của SQLite.
  - `findById(id)`, `findByFeatureId(featureId)`, `findByBranch(branch)`: Truy vấn release theo các tiêu chí.
  - `update(id, input)`: Cập nhật commit SHA, pr_url, status.
  - `list(filter)`, `delete(id)`: Liệt kê và xóa release.
- **Mở rộng `FeatureRepository`**:
  - Bổ sung `getRelease(featureId)` để truy vấn nhanh bản ghi release của feature.

### 1.4. FeatureReleaseService & FeatureService (`apps/orchestrator/src/services/`)
- **`createFeatureBranch(featureId, options)`**:
  - Kiểm tra feature tồn tại trong DB (`FEATURE_NOT_FOUND`).
  - Kiểm tra tính sẵn sàng phát hành qua `assertCanRelease` (REL-002) trừ khi có cờ `skip_readiness_check: true`.
  - Xác định branch name: `feature/<feature-id>` theo `SKILL-git-release.md` hoặc tên tùy chọn.
  - Kiểm tra branch đã tồn tại trong DB: Ném `AppError('BRANCH_ALREADY_EXISTS')`.
  - Gọi `gitCreateBranch` thực thi tạo branch an toàn: Ném `AppError('BRANCH_ALREADY_EXISTS')` nếu branch đã có trong Git.
  - Lưu bản ghi vào bảng `feature_releases`.
  - Ghi structured JSON log.
- **`getFeatureBranchInfo(featureId, repoPath)`**:
  - Truy vấn release từ DB và xác nhận `exists_locally` qua Git.
- **Expose qua `FeatureService`**: Cung cấp `createFeatureBranch` và `getFeatureBranchInfo`.

### 1.5. REST API Endpoints (`apps/orchestrator/src/routes/features.ts`)
- `POST /features/:id/branch` & `POST /api/features/:id/branch`: Tạo branch an toàn (HTTP 201 Created).
  - Trả về HTTP 409 Conflict khi branch đã tồn tại (`BRANCH_ALREADY_EXISTS` hoặc `REPO_DIRTY`).
  - Trả về HTTP 422 Unprocessable Entity khi feature bị chặn phát hành (`FEATURE_RELEASE_BLOCKED`).
  - Trả về HTTP 400 Bad Request khi tên branch không hợp lệ (`INVALID_BRANCH_NAME`) hoặc base ref không tồn tại (`BASE_REF_NOT_FOUND`).
  - Trả về HTTP 404 Not Found khi feature không tồn tại (`FEATURE_NOT_FOUND`).
- `GET /features/:id/branch` & `GET /api/features/:id/branch`: Lấy thông tin branch feature (HTTP 200 / 404).

## 2. Tiêu Chí Nghiệm Thu & Bằng Chứng

### Tiêu chí cốt lõi: Branch trùng → lỗi
- [x] **Nghiệm thu 1: Tạo branch feature an toàn với tên mặc định feature/<feature-id>**
  - Khi feature đủ điều kiện phát hành, hệ thống tạo branch mới theo chuẩn `feature/<feature-id>` trỏ tới base branch (`main`), trả về commit SHA 40 ký tự và trạng thái `BRANCH_CREATED`.
  - *Bằng chứng*: `test/rel-003.test.ts` (Nghiệm thu 1) & `apps/orchestrator/src/__tests__/feature-release-service.test.ts`.
- [x] **Nghiệm thu 2: Branch trùng -> ném lỗi BRANCH_ALREADY_EXISTS, tuyệt đối không ghi đè (Branch trùng → lỗi)**
  - Khi gọi tạo branch mà branch đó đã tồn tại trong Git hoặc DB, hệ thống lập tức ném lỗi `AppError('BRANCH_ALREADY_EXISTS')`, trả về mã HTTP 409 Conflict, bảo vệ 100% không ghi đè dữ liệu branch cũ.
  - *Bằng chứng*: `test/rel-003.test.ts` (Nghiệm thu 2), `packages/shared/src/__tests__/git.test.ts`, và `packages/db/src/__tests__/feature-release-repository.test.ts`.
- [x] **Nghiệm thu 3: Chặn tạo branch feature khi chưa đạt release readiness (REL-002)**
  - Khi feature có task bắt buộc chưa `DONE` hoặc thiếu task trong DB, `createFeatureBranch` bị chặn với lỗi `FEATURE_RELEASE_BLOCKED`, trừ khi caller truyền cờ `skip_readiness_check: true`.
  - *Bằng chứng*: `test/rel-003.test.ts` (Nghiệm thu 3).
- [x] **Nghiệm thu 4: Chặn tạo branch khi repo dirty (có file chưa commit)**
  - Tuân thủ quy định an toàn tại `FND-006` và `SKILL-git-release.md`, khi working tree có thay đổi chưa commit, lệnh tạo branch bị chặn với lỗi `AppError('REPO_DIRTY')`.
  - *Bằng chứng*: `test/rel-003.test.ts` (Nghiệm thu 4).
- [x] **Nghiệm thu 5: Từ chối tên branch không đúng định dạng Git (INVALID_BRANCH_NAME)**
  - Tên branch chứa dấu cách, ký tự đặc biệt, slash ở đầu/cuối, đuôi `.lock`, `..` bị từ chối với lỗi `AppError('INVALID_BRANCH_NAME')` (HTTP 400).
  - *Bằng chứng*: `test/rel-003.test.ts` (Nghiệm thu 5) & `packages/shared/src/__tests__/git.test.ts`.
- [x] **Nghiệm thu 6: Tùy chọn checkout: true chuyển sang branch mới tạo**
  - Khi cờ `checkout: true` được kích hoạt, HEAD của working tree được chuyển an toàn sang branch mới.
  - *Bằng chứng*: `test/rel-003.test.ts` (Nghiệm thu 6).
- [x] **Nghiệm thu 7: Lưu vết đầy đủ vào bảng feature_releases trong SQLite**
  - Thông tin release (`feature_id`, `branch`, `base_branch`, `commit_sha`, `status`, `created_at`) được ghi nhận trong bảng `feature_releases`.
  - *Bằng chứng*: `test/rel-003.test.ts` (Nghiệm thu 7) & `packages/db/src/__tests__/feature-release-repository.test.ts`.
- [x] **Nghiệm thu 8: REST API endpoints POST và GET /features/:id/branch hoạt động chính xác**
  - Endpoint `POST /features/:id/branch` tạo branch trả về HTTP 201, trả về HTTP 409 khi branch trùng; `GET /features/:id/branch` trả về thông tin branch đã tạo.
  - *Bằng chứng*: `test/rel-003.test.ts` (Nghiệm thu 8).
