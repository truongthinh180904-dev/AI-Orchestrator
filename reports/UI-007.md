# Báo cáo nghiệm thu UI-007: Pause/Resume/Stop/Approve — Điều khiển backend thật

## 1. Mục tiêu và Tiêu chí nghiệm thu
- **Nhiệm vụ theo ROADMAP.md**:
  - `UI-007`: Pause/Resume/Stop/Approve
  - **Dependencies**: `ORC-003` (Scheduler tuần tự, lock 1 agent), `ORC-007` (Chế độ review: plan chờ approve mới chạy)
  - **Tiêu chí nghiệm thu**: `Điều khiển backend thật`
- **Các thành phần đã triển khai**:
  1. **Mở rộng API Client (`apps/dashboard/src/lib/api.ts`)**:
     - `getSchedulerStatus()`: Truy vấn trạng thái scheduler thời gian thực (`GET /api/scheduler/status`).
     - `startScheduler(options?)`: Khởi động sequential worker loop (`POST /api/scheduler/start`).
     - `pauseScheduler()`: Tạm dừng bộ điều phối scheduler (`POST /api/scheduler/pause`).
     - `resumeScheduler()`: Tiếp tục điều phối tác vụ (`POST /api/scheduler/resume`).
     - `stopScheduler()`: Dừng khẩn cấp scheduler và hủy các tác vụ active (`POST /api/scheduler/stop`).
     - `stepScheduler(options?)`: Kích hoạt bước điều phối tiếp theo (`POST /api/scheduler/next`).
     - `releaseSchedulerLock()`: Giải phóng khóa agent lock cưỡng bức (`POST /api/scheduler/release-lock`).
     - `stopRun(runId, options?)`: Dừng tiến trình worker riêng biệt theo Run ID (`POST /api/runs/:id/stop`).
     - `listPlans(filter?)`: Lấy danh sách kế hoạch kèm bộ lọc (`GET /api/plans`).
     - `getPlan(id)` & `getPlanReview(id)`: Lấy chi tiết kế hoạch và bản tóm tắt review phân tích DAG stages, scope files và warnings (`GET /api/plans/:id/review`).
     - `approvePlan(id, input?)`: Phê duyệt kế hoạch kèm tên reviewer và ghi chú (`POST /api/plans/:id/approve`).
     - `rejectPlan(id, input)`: Từ chối kế hoạch bắt buộc lý do (`POST /api/plans/:id/reject`).
     - `submitPlanForReview(id)`: Gửi lại kế hoạch chờ thẩm định lại (`POST /api/plans/:id/submit`).
     - `executePlan(id, input?)`: Thực thi kế hoạch đã duyệt (`POST /api/plans/:id/execute`).
     - `transitionTask(id, status, options?)`: Điều khiển chuyển đổi trạng thái tác vụ (`POST /api/tasks/:id/transition`).
     - `retryTask(id, options?)`: Thử lại tác vụ theo chính sách retry policy (`POST /api/tasks/:id/retry`).
  2. **Component Bảng Điều Khiển Hệ Thống `SystemControls` (`apps/dashboard/src/components/SystemControls.tsx`)**:
     - **Thanh trạng thái Scheduler (ORC-003)**:
       - Huy hiệu trạng thái thời gian thực: `▶️ ĐANG CHẠY (RUNNING)`, `⏸️ TẠM DỪNG (PAUSED)`, hoặc `⏹️ SẴN SÀNG (IDLE)`.
       - Thẻ chỉ số: Số tác vụ READY, Task ID đang chạy, Run ID đang chạy, và tình trạng Khóa Agent (`🔒 Đang khóa (PID: ...)` vs `🔓 Khóa tự do`).
     - **Bộ nút điều khiển Scheduler**:
       - Nút "Tạm Dừng (Pause)" (`btn-pause-scheduler`): gọi `pauseScheduler()`. Vô hiệu hóa khi đã paused hoặc đang gửi yêu cầu.
       - Nút "Tiếp Tục (Resume)" (`btn-resume-scheduler`): gọi `resumeScheduler()`. Vô hiệu hóa khi không paused hoặc đang gửi yêu cầu.
       - Nút "Dừng Khẩn Cấp (Stop)" (`btn-stop-scheduler`): kích hoạt mở hộp thoại xác nhận.
       - Nút "Bắt Đầu Vòng Lặp (Start)" (`btn-start-scheduler`): khởi động sequential scheduler.
       - Nút "Chạy 1 Bước (Step Next)" (`btn-step-scheduler`): điều phối một tác vụ tiếp theo.
       - Nút "Giải Phóng Khóa" (`btn-release-lock`): giải phóng agent lock cưỡng bức.
       - Ô nhập "Dừng Run riêng biệt" (`input-target-run-id`) và nút "Dừng Run" (`btn-stop-run`).
     - **Hộp thoại xác nhận trước khi Stop (`modal-confirm-stop`)**:
       - Tuân thủ nguyên tắc `SKILL-nextjs-dashboard.md`: "xác nhận trước khi Stop".
       - Cảnh báo an toàn rõ ràng về tác động hủy tiến trình worker (gửi tín hiệu SIGTERM/SIGKILL).
       - Ô nhập lý do dừng (`input-stop-reason`) và tùy chọn cưỡng bức (`checkbox-stop-force`).
       - Nút xác nhận `btn-confirm-stop` và nút hủy bỏ `btn-cancel-stop`.
     - **Thẩm định & Phê duyệt Kế hoạch (ORC-007)**:
       - Banner thực thi quy tắc cốt lõi: **"Chưa duyệt → không thực thi!"** (`banner-approval-rule`).
       - Bộ lọc trạng thái kế hoạch (`filter-plan-status`) và danh sách thẻ kế hoạch (`plan-item-${id}`).
       - Khung chi tiết thẩm định: Hiển thị trạng thái phê duyệt (`plan-approval-status`), điều kiện thực thi (`plan-can-execute`), số file phạm vi duy nhất (`plan-scope-files`), số tầng thực thi DAG (`plan-dag-stages`), cảnh báo cấu trúc (`plan-warnings`), và bảng danh sách tác vụ (`plan-tasks-table`).
       - Form hành động: Nhập người thẩm định (`input-reviewer-name`), ghi chú duyệt (`input-approve-comments`), lý do từ chối (`input-reject-reason`).
       - Nút "Phê Duyệt (Approve)" (`btn-approve-plan`), "Từ Chối (Reject)" (`btn-reject-plan`), "Gửi Lại Thẩm Định (Submit)" (`btn-submit-plan`).
       - Nút "Thực Thi Kế Hoạch (Execute)" (`btn-execute-plan`): Vô hiệu hóa (`disabled`) khi kế hoạch chưa ở trạng thái `APPROVED` nhằm ngăn chặn vi phạm quy tắc.
     - **Chất lượng thao tác & Phản hồi an toàn**:
       - Toàn bộ nút điều khiển tự động `disabled` trong suốt thời gian API call đang xử lý (`isSubmitting`).
       - Banner báo lỗi từ backend (`controls-error-banner`) kèm nút đóng (`btn-dismiss-error`).
       - Banner thông báo thành công (`controls-success-banner`) kèm nút đóng (`btn-dismiss-success`).
  3. **Trang Dashboard & Định tuyến**:

## 3. Bằng chứng kiểm tra Tiêu chí Nghiệm thu (Điều khiển backend thật)

### 3.1. Nghiệm thu qua Test Tích Hợp Backend Thật (`test/ui-007.test.ts`)
Khởi tạo cơ sở dữ liệu SQLite in-memory, chạy migrations đầy đủ, khởi động backend Orchestrator Fastify thật và gọi qua ApiClient:

1. **Nghiệm thu 1: Pause và Resume Scheduler qua API client với backend Fastify thật**
   - Ban đầu `getSchedulerStatus()` ghi nhận `isPaused: false`.
   - Gọi `api.pauseScheduler()` (POST `/api/scheduler/pause`), backend cập nhật `isPaused: true`. Khi paused, gọi `stepScheduler()` bị từ chối với lý do `SCHEDULER_PAUSED`.
   - Gọi `api.resumeScheduler()` (POST `/api/scheduler/resume`), backend phục hồi `isPaused: false`.
   - *Bằng chứng*: `test/ui-007.test.ts` (Nghiệm thu 1) — PASS.

2. **Nghiệm thu 2: Stop Scheduler và Stop Run qua API client với backend thật**
   - Gọi `api.stopScheduler()` (POST `/api/scheduler/stop`), backend dừng vòng lặp điều phối và trả về `{ stopped: true, isRunning: false }`.
   - Seed tiến trình run `RUNNING` trong database, gọi `api.stopRun('run-ctrl-stop-test', { reason: 'Emergency operator stop', force: true })`, backend cập nhật trạng thái run sang `CANCELLED`/`STOPPED`.
   - *Bằng chứng*: `test/ui-007.test.ts` (Nghiệm thu 2) — PASS.

3. **Nghiệm thu 3: Phê duyệt Kế hoạch (Approve Plan) cập nhật trạng thái APPROVED trong backend thật**
   - Tạo kế hoạch `plan-ctrl-01` ở trạng thái `PENDING_APPROVAL`.
   - `getPlanReview()` ban đầu trả về `is_approved: false`, `can_execute: false`, `requires_approval: true`.
   - Gọi `api.approvePlan('plan-ctrl-01', { approved_by: 'security-reviewer', comments: 'Kiểm toán phạm vi hợp lệ' })`.
   - Backend cập nhật `status: 'APPROVED'`, `approved_by: 'security-reviewer'`, `approved_at`.
   - `getPlanReview()` sau đó xác nhận `is_approved: true`, `can_execute: true`, `requires_approval: false`.
   - *Bằng chứng*: `test/ui-007.test.ts` (Nghiệm thu 3) — PASS.

4. **Nghiệm thu 4: Từ chối kế hoạch (Reject) kèm lý do và Gửi lại (Submit for review) qua API**
   - Gọi `api.rejectPlan('plan-ctrl-02', { reason: 'Phát hiện file cấu hình nhạy cảm trong phạm vi', rejected_by: 'lead-auditor' })`.
   - Backend cập nhật `status: 'REJECTED'` và lưu `rejection_reason`.
   - Gọi `api.submitPlanForReview('plan-ctrl-02')`, backend chuyển trạng thái từ `REJECTED` về lại `PENDING_APPROVAL`.
   - *Bằng chứng*: `test/ui-007.test.ts` (Nghiệm thu 4) — PASS.

5. **Nghiệm thu 5: Tuân thủ quy tắc "Chưa duyệt → không thực thi" — Chặn thực thi kế hoạch chưa duyệt**
   - Tạo kế hoạch `plan-ctrl-unapproved` ở trạng thái `PENDING_APPROVAL`.
   - Gọi `api.executePlan('plan-ctrl-unapproved')` bị backend từ chối với HTTP 400 Bad Request và mã lỗi `PLAN_NOT_APPROVED`.
   - Sau khi phê duyệt qua `api.approvePlan`, gọi `api.executePlan` thành công với trạng thái `EXECUTING`.
   - *Bằng chứng*: `test/ui-007.test.ts` (Nghiệm thu 5) — PASS.

6. **Nghiệm thu 6: Giải phóng khóa Agent Lock cưỡng bức qua API releaseSchedulerLock**
   - Seed bản ghi khóa trong bảng `agent_locks`.
   - Gọi `api.releaseSchedulerLock()`, backend giải phóng khóa và trả về `released: true`. Truy vấn `getSchedulerStatus()` xác nhận `activeLock: null`.
   - *Bằng chứng*: `test/ui-007.test.ts` (Nghiệm thu 6) — PASS.

7. **Nghiệm thu 7: Điều khiển chuyển đổi trạng thái Task qua API client**
   - Gọi `api.transitionTask('TSK-CTRL-01', 'CANCELLED')` chuyển task từ `READY` sang `CANCELLED`.
   - Gọi `api.retryTask('TSK-CTRL-01')` trên task `FAILED` kích hoạt chính sách thử lại, chuyển task sang `READY` và trả về `retried: true`.
   - *Bằng chứng*: `test/ui-007.test.ts` (Nghiệm thu 7) — PASS.
