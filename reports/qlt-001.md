## 1. Kết Quả Thực Hiện

### 1.1. Domain Models & Schemas (`packages/shared/src/quality/types.ts`)
- **Các stage kiểm định tiêu chuẩn**:
  - `format`: Kiểm tra định dạng mã nguồn (vd: `prettier --check .`, `pnpm format:check`).
  - `lint`: Phân tích tĩnh chất lượng code (vd: `eslint .`, `pnpm lint`).
  - `typecheck`: Kiểm tra kiểu tĩnh (vd: `tsc --noEmit`, `pnpm typecheck`).
  - `test`: Chạy bộ kiểm thử đơn vị/tích hợp (vd: `vitest run`, `pnpm test`).
  - `build`: Kiểm tra khả năng build sản phẩm (vd: `pnpm build`, `tsc`). Mặc định `required: false` cho phép linh hoạt với repo chỉ chứa script/module.
  - `custom`: Các lệnh bổ trợ mở rộng (vd: `audit`, `security check`).
- **Schema `QualityCommandDefinitionSchema`**:
  - Định nghĩa lệnh chuẩn hóa, bảo đảm an toàn: `id`, `stage`, `name`, `command`, `exe`, `args[]`, `cwd`, `env`, `timeout_ms`, `enabled`, `required`, `continueOnError`.
  - Phù hợp với quy tắc kỹ thuật AGENTS.md: cấm `shell: true`, yêu cầu `child_process.spawn(exe, argsArray)`.
- **Schema `RepoQualityConfigSchema` & `RepoQualityConfigInputSchema`**:
  - Cung cấp mô hình cấu hình hoàn chỉnh theo từng repo: `repo_id`, `repo_path`, các stage `format`, `lint`, `typecheck`, `test`, `build`, `custom_commands`, `stop_on_first_failure`, `default_timeout_ms`.
  - Hỗ trợ cú pháp linh hoạt từ file JSON, sheet Excel/CSV, hoặc REST API (chuỗi lệnh, mảng tham số, hoặc đối tượng stage đầy đủ).
- **Hàm `getExecutionPipeline(config)`**:
  - Trả về danh sách lệnh kiểm định sẵn sàng thực thi theo đúng thứ tự chuẩn hóa: `format -> lint -> typecheck -> test -> build -> custom commands`.
  - Tự động bỏ qua các stage `null` hoặc `enabled: false`.

### 1.2. Command Line Parser & Normalizer (`packages/shared/src/quality/command-parser.ts`)
- **`parseCommandLine(commandLine)`**:
  - Tách chuỗi dòng lệnh thành `{ exe, args[] }` một cách an toàn và mạnh mẽ.
  - Xử lý trọn vẹn dấu nháy đơn (`'...'`), dấu nháy kép (`"..."`), ký tự thoát (`\ `), và khoảng trắng.
  - Bắt lỗi khi lệnh rỗng, nháy chưa đóng, hoặc ký tự thoát bị lơ lửng bằng `AppError('INVALID_COMMAND')`.
- **`normalizeQualityCommand(stage, input, options)`**:
  - Chuyển đổi mọi dạng input (string, array, object) thành `QualityCommandDefinition` hợp lệ.
  - Tự động gán nhãn thân thiện, thư mục làm việc `cwd`, timeout mặc định, và cờ `required` theo từng stage.

### 1.3. Cơ Chế Đọc Cấu Hình Đa Nguồn (`packages/shared/src/quality/quality-config-loader.ts`)
- **Đọc từ file cấu hình trong repository ("Đọc từ config")**:
  - Ưu tiên 1: `quality.json` hoặc `.quality.json` tại thư mục gốc của repo.
  - Ưu tiên 2: `.orchestrator/quality.json` hoặc `.orchestrator.json`.
  - Ưu tiên 3: `package.json` với trường `qualityGate` hoặc `quality` hoặc `orchestrator.quality`.
  - Tự động nhận diện từ `package.json.scripts` khi không có file cấu hình riêng (nhận diện chính xác `pnpm`, `yarn`, `bun`, `npm`).
- **Đọc từ Workbook `ParsedConfig` (Sheet 'Config')**:
  - Phân tích danh sách `verify_commands` hoặc `quality_commands` và tự động phân loại về từng stage.
  - Đọc các thiết lập stage trực tiếp từ `settings` / `raw` (vd: `format_command`, `lint_command`, `typecheck_command`, `test_command`, `build_command`).
- **Phân giải cấu hình tổng hợp `resolveRepoQualityConfig(options)`**:
  - Kết hợp theo thứ tự ưu tiên: `overrides (cao nhất) -> repo quality.json -> package.json -> workbook config -> task-specific test_commands`.
  - Hỗ trợ `task.test_commands`: tự động ghi đè hoặc bổ sung stage `test` cho từng tác vụ riêng biệt.

### 1.4. Tầng Dịch Vụ `QualityConfigService` (`apps/orchestrator/src/services/quality-config-service.ts`)
- Tích hợp với `RepositoryRegistry` để tra cứu đường dẫn repo canonical theo ID hoặc path.
- Tích hợp với `TaskRepository` để lấy cấu hình kiểm định chuyên biệt cho từng task ID (`getConfigForTask`).
- Cung cấp khả năng lưu cấu hình repo vào `.orchestrator/quality.json` (`saveRepoQualityConfig`).
- Cung cấp hàm kiểm định `validateConfig` qua schema Zod.

### 1.5. Tầng REST API (`apps/orchestrator/src/routes/quality.ts`)
- `GET /repos/:id/quality-config` & `GET /api/repos/:id/quality-config`: Đọc cấu hình kiểm định của repo theo ID hoặc đường dẫn.
- `GET /tasks/:id/quality-config` & `GET /api/tasks/:id/quality-config`: Đọc cấu hình kiểm định cho một task cụ thể.
- `POST /quality/resolve` & `POST /api/quality/resolve`: Phân giải cấu hình động từ tham số payload, workbook hoặc overrides.
- `PUT /repos/:id/quality-config` & `PUT /api/repos/:id/quality-config`: Cập nhật cấu hình kiểm định của repo và lưu trữ vào `.orchestrator/quality.json`.
