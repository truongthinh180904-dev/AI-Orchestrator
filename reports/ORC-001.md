## Thông tin Task
- **Mã Task**: ORC-001
- **Mô tả**: State machine task: `TODO→READY→RUNNING→VERIFYING→DONE`, `FAILED`, `BLOCKED`, `PAUSED`, `CANCELLED`

## 1. Kết Quả Thực Hiện

### 1.1. Bảng Trạng Thái & Quy Tắc State Machine (`packages/shared/src/state/`)
Đã triển khai module State Machine cho Task trong `@ai-orchestrator/shared`:
- **9 Trạng thái tiêu chuẩn**: `TODO`, `READY`, `RUNNING`, `VERIFYING`, `DONE`, `FAILED`, `BLOCKED`, `PAUSED`, `CANCELLED`.
- **Chu trình tuyến tính chính**:
  ```
  TODO ──► READY ──► RUNNING ──► VERIFYING ──► DONE
  ```
- **Các quy tắc chuyển đổi chặt chẽ**:
  - `TODO`: Chỉ được chuyển sang `READY`, `BLOCKED`, `CANCELLED`. Cấm nhảy cóc sang `RUNNING`, `VERIFYING`, `DONE`.
  - `READY`: Chỉ được chuyển sang `RUNNING`, `PAUSED`, `BLOCKED`, `CANCELLED`, `TODO`. Cấm nhảy cóc sang `VERIFYING`, `DONE`.
  - `RUNNING`: Chỉ được chuyển sang `VERIFYING` (hoàn tất thực thi để vào kiểm thử), `FAILED`, `PAUSED`, `BLOCKED`, `CANCELLED`. Bắt buộc phải qua `VERIFYING`, không được nhảy thẳng sang `DONE`.
  - `VERIFYING`: Chỉ được chuyển sang `DONE` (khi kiểm thử đạt), `FAILED`, `PAUSED`, `BLOCKED`, `CANCELLED`.
  - `DONE`: Trạng thái kết thúc tuyệt đối (terminal), không cho phép bất kỳ chuyển đổi nào ra khỏi `DONE`.
  - `FAILED`: Cho phép chuyển sang `READY` (retry theo chính sách retry), `TODO`, `CANCELLED`.
  - `BLOCKED`: Cho phép chuyển sang `READY` (khi gỡ chặn), `TODO`, `FAILED`, `CANCELLED`.
  - `PAUSED`: Cho phép chuyển sang `READY`, `RUNNING`, `VERIFYING`, `TODO`, `FAILED`, `CANCELLED`.
  - `CANCELLED`: Cho phép chuyển sang `TODO` (reopen).
- **Hàm xác thực & Ngoại lệ**:
  - `isValidTaskTransition(from, to, options?)`: Kiểm tra tính hợp lệ Boolean.
  - `getAllowedTaskTransitions(from)`: Trả về danh sách trạng thái kế tiếp được phép.
  - `isTerminalTaskStatus(status)`: Nhận diện trạng thái kết thúc.
  - `assertValidTaskTransition(from, to, options?)`: Ném `AppError('ILLEGAL_STATE_TRANSITION', ...)` khi chuyển đổi trái phép.

### 1.2. Domain Class `TaskStateMachine`
- Quản lý trạng thái hiện tại, kiểm tra `canTransitionTo()`, thực thi `transition()`.
- Lưu trữ lịch sử chuyển đổi `history: [{ from, to, timestamp, reason, meta }]`.
- Đăng ký observer `onTransition(listener)` và hỗ trợ `reset()`.

### 1.3. Tầng Database Repository (`packages/db/src/repositories/task-repository.ts`)
- Thêm phương thức `transitionStatus(id, newStatus, options)`: Thực hiện kiểm tra tính hợp lệ của chuyển đổi bằng `assertValidTaskTransition` trước khi chạy câu lệnh `UPDATE tasks SET status = ?, attempts = ?, updated_at = ? WHERE id = ?`.
- Hỗ trợ cờ `incrementAttempt: true` tự động tăng số lần thử khi task bắt đầu chạy.
- Cập nhật `updateStatus(id, newStatus, options)` tích hợp tùy chọn `enforceTransitions: true`.

### 1.4. Tầng Dịch Vụ Orchestrator (`apps/orchestrator/src/services/task-state-service.ts`)
- Triển khai `TaskStateService` điều phối chuyển đổi trạng thái task trong hệ sinh thái.
- Cung cấp các hàm lifecycle chuyên dụng: `markReady`, `markRunning`, `markVerifying`, `markDone`, `markFailed`, `markBlocked`, `pause`, `resume`, `cancel`.
- Ghi nhận sự kiện `task_transition` vào bảng SQLite `events` khi có `runId`.
- Xuất log JSON có cấu trúc đầy đủ `timestamp`, `level`, `context` (`taskId`, `from`, `to`, `reason`, `attempts`).

### 1.5. Tầng REST API (`apps/orchestrator/src/routes/tasks.ts`)
- `POST /tasks/:id/transition` & `POST /api/tasks/:id/transition`:
  - Nhận payload `{ status, reason?, runId?, incrementAttempt?, force? }`.
  - Validate schema qua `TaskTransitionBodySchema`.
  - Chuyển đổi hợp lệ: trả về HTTP 200 `{ data: updatedTask }`.
  - Chuyển đổi trái phép: trả về HTTP 400 Bad Request với mã lỗi `ILLEGAL_STATE_TRANSITION`.
- `GET /tasks/:id/allowed-transitions` & `GET /api/tasks/:id/allowed-transitions`:
  - Trả về HTTP 200 `{ data: { taskId, currentStatus, allowedTransitions } }`.
