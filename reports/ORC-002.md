## 1. Kết Quả Thực Hiện

### 1.1. Module Phân Giải Phụ Thuộc Domain (`packages/shared/src/resolver/`)
Đã triển khai module `DependencyResolver` trong `@ai-orchestrator/shared`:
- **Hàm kiểm tra thỏa mãn dependency `isDependencySatisfied(status)`**:
  - Trả về `true` duy nhất khi trạng thái của dependency là `DONE`.
  - Mọi trạng thái khác (`TODO`, `READY`, `RUNNING`, `VERIFYING`, `FAILED`, `BLOCKED`, `PAUSED`, `CANCELLED`, `MISSING`, `undefined`, `null`) đều trả về `false`.
- **Hàm phân tích chi tiết `checkTaskDependencies(task, lookup)`**:
  - Trả về đối tượng `TaskDependencyStatus` chứa:
    - `isReady`: boolean xác định task có thể bắt đầu chạy hay không.
    - `currentStatus`: Trạng thái hiện tại của task.
    - `totalDependencies`: Tổng số dependency đã khai báo.
    - `satisfiedDependencies`: Danh sách ID các dependency đã đạt `DONE`.
    - `unsatisfiedDependencies`: Danh sách các dependency chưa `DONE` (kèm trạng thái hiện tại hoặc `MISSING`).
    - `missingDependencies`: Danh sách ID dependency không tìm thấy trong hệ thống.
    - `reason`: Chuỗi mô tả lý do rõ ràng phục vụ audit và hiển thị giao diện.
- **Lớp `DependencyResolver`**:
  - Quản lý tập hợp các task, cung cấp:
    - `getReadyTasks(options)`: Trích xuất danh sách các task đủ điều kiện chạy.
      - **Tiêu chuẩn nghiệm thu cốt lõi ("Chỉ trả task đủ dependency")**: Chỉ các task có 100% dependencies đạt trạng thái `DONE` mới được xuất hiện trong danh sách.
      - Hỗ trợ lọc theo `featureId`, `phase`, `repository`.
      - Mặc định chỉ nhận các task có trạng thái ứng viên `['TODO', 'READY']`.
      - **Sắp xếp thứ tự tất định (deterministic)**:
        1. `priority` giảm dần (độ ưu tiên cao nhất xếp đầu tiên).
        2. `created_at` tăng dần (task tạo trước xếp trước).
        3. `id` tăng dần (theo bảng chữ cái).
      - Hỗ trợ giới hạn `limit` số lượng task trả về.
    - `getNextReadyTask(options)`: Trả về task kế tiếp có độ ưu tiên cao nhất (cho Scheduler ORC-003).
    - `checkTask(taskId)`: Đánh giá chi tiết 1 task.
    - `areDependenciesSatisfied(taskId)`: Kiểm tra nhanh boolean.
    - `getResolutionSummary(options)`: Thống kê toàn diện (ready, blocked, pending, completed).
    - `findBlockedByFailedTasks()`: Xác định các task bị tắc nghẽn do dependency bị `FAILED`, `CANCELLED`, hoặc `BLOCKED`.
- **Hàm helper `resolveReadyTasks(tasks, options)`**: Tiện ích gọi nhanh giải quyết phụ thuộc.

### 1.2. Tầng Database Repository (`packages/db/src/repositories/task-repository.ts`)
- `findReadyTasks(filter, options)`: Tích hợp trực tiếp `DependencyResolver` với dữ liệu truy vấn từ SQLite, đảm bảo tính nhất quán tuyệt đối.
- `getDependencyStatus(taskId)`: Truy vấn trạng thái phụ thuộc chi tiết của một task cụ thể.
- `resolveAndMarkReady(filter)`: Thực hiện trong SQLite transaction:
  - Tự động tìm các task `TODO` có đầy đủ dependencies `DONE`.
  - Chuyển trạng thái sang `READY` với lý do `'Dependencies satisfied (resolved ready)'`.
  - Trả về danh sách toàn bộ các task `READY`.

### 1.3. Tầng Dịch Vụ Orchestrator (`apps/orchestrator/src/services/dependency-resolver-service.ts`)
- Khởi tạo `DependencyResolverService` quản lý luồng điều phối giải quyết phụ thuộc.
- Hỗ trợ cờ `autoTransition: true` tự động đưa các task `TODO` đủ điều kiện vào trạng thái `READY`.
- Tích hợp vào `TaskService` (`apps/orchestrator/src/services/task-service.ts`), cung cấp các hàm `getReadyTasks`, `getNextReadyTask`, `getDependencyStatus`, `resolveReady`.

### 1.4. Tầng REST API (`apps/orchestrator/src/routes/tasks.ts`)
- `GET /tasks/ready` & `GET /api/tasks/ready`:
  - Trả về HTTP 200 `{ data: TaskWithDependencies[] }`.
  - Nhận query params: `feature_id`, `phase`, `autoTransition`, `limit`.
- `GET /tasks/:id/dependency-status` & `GET /api/tasks/:id/dependency-status`:
  - Trả về HTTP 200 `{ data: TaskDependencyStatus }`.
  - Trả về HTTP 404 nếu không tìm thấy task ID.
- `POST /tasks/resolve-ready` & `POST /api/tasks/resolve-ready`:
  - Chuyển đổi các task đủ điều kiện sang `READY` và trả về HTTP 200 `{ data: TaskWithDependencies[] }`.

## 2. Bằng Chứng Nghiệm Thu Từng Tiêu Chí

### Tiêu chí: Chỉ trả task đủ dependency

- [x] **Nghiệm thu 1: Tiêu chí cốt lõi — Chỉ trả task đủ dependency**
  - *Mô tả*: Đồ thị task với nhiều trạng thái khác nhau (`DONE`, `RUNNING`, `TODO`, `FAILED`, `BLOCKED`, `PAUSED`, `CANCELLED`). Task có dependency là `DONE` được trả về. Mọi task có dependency chưa `DONE` (đang chạy, lỗi, tạm dừng, bị chặn, hoặc hủy) đều bị loại bỏ 100%. Kiểm định bất biến: 100% task trả về từ `findReadyTasks()` đều có mọi dependencies ở trạng thái `DONE`.
  - *Bằng chứng*:
    - `packages/shared/src/__tests__/dependency-resolver.test.ts` ("chỉ trả các task có toàn bộ dependencies đã hoàn tất (DONE)")
    - `test/orc-002.test.ts` ("Nghiệm thu 1: Tiêu chí cốt lõi — Chỉ trả task đủ dependency: chỉ trả về các task mà 100% dependencies đã ở trạng thái DONE")

- [x] **Nghiệm thu 2: Tiến trình chuỗi phụ thuộc tuyến tính (Linear Chain: T1 → T2 → T3)**
  - *Mô tả*: Khi T1 chưa `DONE`, T2 và T3 không được trả về. Khi T1 `DONE`, T2 lập tức xuất hiện trong danh sách READY (T3 vẫn chưa). Khi T2 `DONE`, T3 lập tức trở thành READY.
  - *Bằng chứng*:
    - `test/orc-002.test.ts` ("Nghiệm thu 2: Tiến trình chuỗi phụ thuộc tuyến tính (Linear Chain: T1 → T2 → T3)")

- [x] **Nghiệm thu 3: Đồ thị kim cương (Diamond: A → (B, C) → D)**
  - *Mô tả*: D phụ thuộc B và C. Khi B đã `DONE` nhưng C mới đang `RUNNING` hoặc `VERIFYING`, D tuyệt đối KHÔNG được trả về. Chỉ khi cả B và C đều `DONE`, D mới được trả về.
  - *Bằng chứng*:
    - `packages/shared/src/__tests__/dependency-resolver.test.ts` ("chu trình kim cương (Diamond): chỉ trả D khi cả B và C đều DONE")
    - `test/orc-002.test.ts` ("Nghiệm thu 3: Đồ thị kim cương (Diamond: A → (B, C) → D)")

- [x] **Nghiệm thu 4: Sắp xếp theo mức độ ưu tiên (Priority & Deterministic Tie-break)**
  - *Mô tả*: Khi có nhiều task cùng sẵn sàng, danh sách được sắp xếp theo `priority` giảm dần, sau đó theo `created_at` tăng dần và `id` tăng dần. `getNextReadyTask()` trả về task có priority cao nhất.
  - *Bằng chứng*:
    - `packages/shared/src/__tests__/dependency-resolver.test.ts` ("sắp xếp thứ tự task READY theo priority giảm dần, sau đó theo created_at và ID")
    - `test/orc-002.test.ts` ("Nghiệm thu 4: Sắp xếp ưu tiên (Priority) và Deterministic Order")

- [x] **Nghiệm thu 5: Tự động chuyển đổi TODO → READY trong SQLite Transaction**
  - *Mô tả*: `taskRepo.resolveAndMarkReady()` cập nhật trạng thái các task `TODO` đủ điều kiện sang `READY` trong SQLite transaction an toàn. Các task chưa đủ điều kiện giữ nguyên `TODO`.
  - *Bằng chứng*:
    - `test/orc-002.test.ts` ("Nghiệm thu 5: Tự động chuyển đổi TODO → READY (Auto-transition & SQLite Transaction)")

- [x] **Nghiệm thu 6: REST API `GET /tasks/ready`**
  - *Mô tả*: Endpoint `GET /tasks/ready` trả về HTTP 200 kèm danh sách task READY, hỗ trợ lọc theo `feature_id`, `phase`, `autoTransition=true` và `limit`.
  - *Bằng chứng*:
    - `test/orc-002.test.ts` ("Nghiệm thu 6: REST API GET /tasks/ready & GET /api/tasks/ready")

- [x] **Nghiệm thu 7: REST API `GET /tasks/:id/dependency-status`**
  - *Mô tả*: Endpoint `GET /tasks/:id/dependency-status` phân tích chi tiết phụ thuộc của task cụ thể; trả về 404 khi task không tồn tại.
  - *Bằng chứng*:
    - `test/orc-002.test.ts` ("Nghiệm thu 7: REST API GET /tasks/:id/dependency-status")

- [x] **Nghiệm thu 8: REST API `POST /tasks/resolve-ready`**
  - *Mô tả*: Kích hoạt giải quyết phụ thuộc, chuyển đổi các task `TODO` đủ điều kiện sang `READY` và trả về danh sách task `READY`.
  - *Bằng chứng*:
    - `test/orc-002.test.ts` ("Nghiệm thu 8: REST API POST /tasks/resolve-ready")

- [x] **Nghiệm thu 9: Xử lý task có dependency bị FAILED / BLOCKED / MISSING**
  - *Mô tả*: Task có dependency bị `FAILED`, `BLOCKED`, `CANCELLED` hoặc không tồn tại (`MISSING`) không bao giờ được coi là `READY`.
  - *Bằng chứng*:
    - `packages/shared/src/__tests__/dependency-resolver.test.ts` ("tổng hợp trạng thái đồ thị qua getResolutionSummary()", "findBlockedByFailedTasks")
