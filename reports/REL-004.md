## 1. Kết Quả Thực Hiện

### 1.1. Conventional Commits 1.0.0 Specification (`packages/shared/src/models/conventional-commit.ts`)
- **`CONVENTIONAL_COMMIT_TYPES`**: Bộ 11 kiểu commit chuẩn theo chuẩn Conventional Commits 1.0.0 (`feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`, `revert`).
- **`formatConventionalCommit(input)`**: Định dạng commit theo cú pháp `<type>(<scope>)<!>: <subject>` kèm body và footer tùy chọn.
- **`parseConventionalCommit(message)`**: Bóc tách commit message thành cấu trúc `ParsedConventionalCommit` (`type`, `scope`, `is_breaking`, `subject`, `body`, `footer`, `raw`), tự động nhận diện breaking change (`!` hoặc `BREAKING CHANGE:`).
- **`validateConventionalCommit(message)`**: Kiểm định chặt chẽ commit message, ném lỗi `AppError('INVALID_COMMIT_MESSAGE')` nếu vi phạm chuẩn Conventional Commits.
- **`isConventionalCommit(message)`**: Trả về boolean kiểm tra tính hợp lệ của commit message.

### 1.2. Git Commit Engine An Toàn (`packages/shared/src/git.ts`)
- **`gitCommit(repoPath, options)`**:
  - Tự động xác thực commit message theo chuẩn Conventional Commits (`validateConventionalCommit`).
  - Hỗ trợ staging linh hoạt: chỉ định mảng file (`files`), stage toàn bộ (`stageAll`), hoặc commit rỗng (`allowEmpty`).
  - Kiểm tra trạng thái staged (`git diff --cached --name-only`), ném lỗi `AppError('NOTHING_TO_COMMIT')` nếu không có thay đổi staged.
  - Thực thi commit qua `runGitCommand(['commit', '-m', message])` sử dụng `child_process.spawn` an toàn, không chạy qua shell injection.
  - Lấy 40 ký tự SHA commit HEAD qua `git rev-parse HEAD`, xác thực định dạng regex `/^[0-9a-f]{40}$/i`.
  - Trả về đối tượng `GitCommitResult` gồm `commitSha`, `shortSha`, `branch`, `message`, `filesCommitted`, `createdAt`.
- **`gitGetCommitDetails(repoPath, ref)`**: Lấy thông tin chi tiết commit (SHA, tác giả, email, ngày tạo, subject, body).

### 1.3. Release Models & Schemas (`packages/shared/src/models/release.ts`)
- **`CommitFeatureReleaseInputSchema`**: Tham số cho việc commit feature release (`message`, `type`, `scope`, `subject`, `body`, `stage_all`, `files`, `allow_empty`, `repo_path`).
- **`CommitFeatureReleaseResultSchema`**: Kết quả commit release gồm `release_id`, `feature_id`, `branch`, `commit_sha` (40 chars hex), `short_sha`, `message`, `status: 'COMMITTED'`, `files_committed`, `committed_at`.
- **`RecordTaskCommitInputSchema` & `RecordTaskCommitResultSchema`**: Cho phép ghi nhận và lưu trữ commit SHA cho từng task/run vào SQLite database.

### 1.4. FeatureReleaseService & FeatureService (`apps/orchestrator/src/services/`)
- **`commitFeatureRelease(featureId, input)`**:
  - Xác nhận feature tồn tại (`FEATURE_NOT_FOUND`).
  - Kiểm tra release branch đã tạo ở REL-003 (`FEATURE_BRANCH_NOT_FOUND`).
  - Tự động chuẩn hóa message Conventional Commits nếu không cung cấp message: `feat(<featureId>): release feature <name>`.
  - Thực thi `gitCommit` trên working tree của repo.
  - Cập nhật bản ghi `feature_releases` trong SQLite: lưu `commit_sha = gitResult.commitSha`, chuyển `status = 'COMMITTED'`, cập nhật metadata.
  - Ghi JSON structured log với SHA và thông tin release.
- **`getFeatureRelease(featureId)`**: Trả về bản ghi release lưu trong DB gồm `commit_sha` và `status`.
- **Expose qua `FeatureService`**: Cung cấp `commitFeatureRelease` và `getFeatureRelease`.

### 1.5. TaskService Commit Integration (`apps/orchestrator/src/services/task-service.ts`)
- **`recordTaskCommit(taskId, input)`**:
  - Hỗ trợ commit thay đổi cho task logic (`feat(TSK-xxx): ...`).
  - Lưu SHA (`git rev-parse HEAD`) trực tiếp vào trường `commit_sha` của bảng `runs` trong SQLite database (theo đúng `SKILL-git-release.md`).

### 1.6. REST API Endpoints
- `POST /features/:id/commit` & `POST /api/features/:id/commit`: Commit feature release, lưu SHA và cập nhật status sang `COMMITTED` (HTTP 201).
- `GET /features/:id/release` & `GET /api/features/:id/release`: Lấy thông tin release với `commit_sha` đã lưu trong DB (HTTP 200).
- `POST /tasks/:id/commit` & `POST /api/tasks/:id/commit`: Thực hiện và ghi nhận commit SHA cho task run trong DB (HTTP 201).
- Centralized Error Handling: xử lý `INVALID_COMMIT_MESSAGE` (400), `NOTHING_TO_COMMIT` (400), `RELEASE_NOT_FOUND` (404), `GIT_COMMIT_FAILED` (500).

  - *Bằng chứng*: `test/rel-004.test.ts` (Nghiệm thu 2) & `packages/shared/src/__tests__/conventional-commit.test.ts`.

  - *Bằng chứng*: `test/rel-004.test.ts` (Nghiệm thu 3) & `packages/shared/src/__tests__/git.test.ts`.
