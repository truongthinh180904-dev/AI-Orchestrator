## 1. Kết Quả Thực Hiện

### 1.1. Cơ sở dữ liệu & Migration 003 (`packages/db/migrations/003_checkpoints.sql`)
- Khởi tạo bảng `checkpoints`:
  - `id TEXT PRIMARY KEY`: Khóa chính định danh checkpoint (UUID).
  - `task_id TEXT NOT NULL REFERENCES tasks(id) ON DELETE CASCADE`: Khóa ngoại liên kết task.
  - `run_id TEXT REFERENCES runs(id) ON DELETE CASCADE`: Khóa ngoại liên kết run (hỗ trợ checkpoint gắn liền với lần chạy cụ thể).
  - `attempt INTEGER NOT NULL DEFAULT 1`: Số thứ tự attempt tương ứng.
  - `step TEXT NOT NULL`: Tên bước hoặc mốc thực thi (ví dụ: `run_started`, `compile_code`, `test_execution`, `run_completed`, `run_failed`).
  - `status TEXT NOT NULL DEFAULT 'COMPLETED'`: Trạng thái bước (`PENDING`, `IN_PROGRESS`, `COMPLETED`, `FAILED`, `SKIPPED`).
  - `data TEXT NOT NULL DEFAULT '{}'`: Dữ liệu ngữ cảnh/snapshot trạng thái dạng JSON có cấu trúc.
  - `created_at TEXT NOT NULL`: Mốc thời gian ISO-8601 UTC.
  - Các chỉ mục tối ưu hóa: `idx_checkpoints_task_id`, `idx_checkpoints_run_id`, `idx_checkpoints_task_attempt`.
- Khai thác bảng `reports` từ Migration 001 qua `ReportRepository`:
  - Quản lý các báo cáo nghiệm thu, kiểm định chất lượng, test summary gắn liền với run hoặc task.

### 1.2. Lớp Repositories (`packages/db/src/repositories/`)
- **`CheckpointRepository`**:
  - `create(input)`: Tạo checkpoint với dữ liệu JSON hợp lệ và timestamp UTC.
  - `getById(id)`: Lấy thông tin checkpoint đã qua xác thực zod.
  - `findByTaskId(taskId, filter)`: Lọc checkpoint theo task, attempt, step, status.
  - `findByRunId(runId)`: Lấy toàn bộ checkpoint trong một run theo thứ tự thời gian.
  - `getLatestByTaskId(taskId)`: Lấy checkpoint mới nhất của task.
  - `getLatestByRunId(runId)`: Lấy checkpoint mới nhất của run.
  - `countByRunId(runId)`: Đếm số lượng checkpoints trong một run.
  - `delete(id)`: Xóa checkpoint.
- **`ReportRepository`**:
  - `create(input)`: Tạo bản ghi báo cáo nghiệm thu.
  - `getById(id)`: Lấy báo cáo theo ID.
  - `findByRunId(runId, filter)`: Lấy danh sách báo cáo của một run.
  - `findByTaskId(taskId)`: Lấy danh sách báo cáo của toàn bộ các run thuộc task.
  - `countByRunId(runId)`: Đếm số lượng báo cáo của run.
  - `delete(id)`: Xóa báo cáo.

### 1.3. Mô Hình Dữ Liệu `@ai-orchestrator/shared`
- `CheckpointSchema`, `CreateCheckpointInputSchema`, `CheckpointFilterSchema`.
- `ReportSchema`, `CreateReportInputSchema`, `ReportFilterSchema`.
- `RunOutcomeSchema`: `'SUCCESS' | 'ERROR' | 'TIMEOUT' | 'CANCELLED' | 'IN_PROGRESS' | 'UNKNOWN'`.
- `RunResultSummarySchema`: Tổng hợp kết quả một run gồm `outcome`, `success`, `exit_code`, `duration_ms`, `error_message`, `event_count`, `checkpoint_count`, `report_count`.
- `TaskAttemptHistoryItemSchema`: Chi tiết một lần thử gồm `attempt`, `run`, `result`, `checkpoints`, `reports`.
- `TaskRunHistorySchema`: Lịch sử toàn bộ các lần chạy của task.
- `RunDetailSchema`: Cấu trúc dữ liệu phục vụ "Truy lại từng run", bao gồm `run`, `task`, `result`, `checkpoints`, `reports`, `events`, `eventStats`.

### 1.4. Tầng Dịch Vụ (`apps/orchestrator/src/services/`)
- **`TaskHistoryService`**:
  - `computeRunResult(run)`: Tự động tính toán thời lượng chạy `duration_ms` từ `started_at` và `finished_at`, ánh xạ trạng thái sang `outcome`, trích xuất thông điệp lỗi tự động từ `events` (sự kiện `stderr` hoặc `result` error payload).
  - `getTaskRunHistory(taskId)`: Tổng hợp toàn bộ các lần chạy của task theo thứ tự attempt, đi kèm kết quả, checkpoint và report của từng lần chạy.
  - `getRunDetail(runId)`: Triển khai tiêu chuẩn "Truy lại từng run", cung cấp toàn diện metadata, task liên kết, phân tích kết quả, danh sách checkpoints, reports, danh sách events và thống kê phân bổ theo loại event (`eventStats.byType`).
- **`TaskService` & `RunService`**:
  - Tích hợp `TaskHistoryService` để cung cấp các API tra cứu lịch sử, truy lại run, quản lý checkpoint và report.
- **`TaskScheduler`**:
  - Tích hợp tự động ghi nhận checkpoint:
    - Khi khởi động tiến trình worker: ghi checkpoint `run_started` (`status: 'IN_PROGRESS'`).
    - Khi hoàn thành thành công: ghi checkpoint `run_completed` (`status: 'COMPLETED'`) kèm mã `exit_code`.
    - Khi thất bại hoặc timeout: ghi checkpoint `run_failed` (`status: 'FAILED'`) kèm lý do và mã `exit_code`.
    - Khi bị dừng/hủy: ghi checkpoint `run_cancelled` (`status: 'FAILED'`).

### 1.5. Tầng REST API (`apps/orchestrator/src/routes/`)
- **Task Endpoints**:
  - `GET /tasks/:id/history` & `GET /api/tasks/:id/history`: Lịch sử các lần chạy đa attempt.
  - `GET /tasks/:id/checkpoints` & `GET /api/tasks/:id/checkpoints`: Danh sách checkpoint của task.
  - `POST /tasks/:id/checkpoints` & `POST /api/tasks/:id/checkpoints`: Tạo checkpoint mới cho task.
  - `GET /tasks/:id/checkpoints/latest` & `GET /api/tasks/:id/checkpoints/latest`: Lấy checkpoint gần nhất.
- **Run Endpoints ("Truy lại từng run")**:
  - `GET /runs/:id/detail` & `GET /api/runs/:id/detail`: Truy lại thông tin chi tiết của bất kỳ run nào.
  - `GET /runs/:id/checkpoints` & `GET /api/runs/:id/checkpoints`: Danh sách checkpoints gắn với run.
  - `POST /runs/:id/checkpoints` & `POST /api/runs/:id/checkpoints`: Tạo checkpoint gắn với run.
  - `GET /runs/:id/reports` & `GET /api/runs/:id/reports`: Danh sách báo cáo gắn với run.
  - `POST /runs/:id/reports` & `POST /api/runs/:id/reports`: Tạo báo cáo gắn với run.
