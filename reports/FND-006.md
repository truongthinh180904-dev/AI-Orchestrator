# Báo cáo Nghiệm thu FND-006

## Thông tin Task
- **ID**: `FND-006`
- **Mô tả**: Hàm `checkRepoClean(path)` dùng `git status --porcelain`
- **Dependency**: `FND-001` (đã hoàn thành)
- **Tiêu chuẩn nghiệm thu**: Repo bẩn → trả lỗi, không ghi đè

## Các thành phần đã triển khai

1. **Tiện ích Git Core (`packages/shared/src/git.ts`)**:
   - Sử dụng `child_process.spawn('git', args, { cwd: repoPath, stdio: ['ignore', 'pipe', 'pipe'] })`, tuyệt đối tuân thủ quy tắc an toàn (cấm `exec`/`shell: true` với input động).
   - Kiểm tra đường dẫn tồn tại (`PATH_NOT_FOUND`) và là thư mục (`NOT_A_DIRECTORY`).
   - Kiểm tra thư mục Git hợp lệ (`NOT_A_GIT_REPO`).
   - Hàm `parseGitPorcelain(rawOutput)`: Phân tích cú pháp đầu ra từ `git status --porcelain` (v1 format), trích xuất `indexStatus`, `workTreeStatus`, đường dẫn file `path`, hỗ trợ phát hiện file đổi tên (`old -> new`) và unquote đường dẫn có khoảng trắng.
   - Hàm `getRepoStatus(repoPath, options)`: Trả về trạng thái chi tiết `{ isClean, files, raw }`, hỗ trợ cấu hình `allowedFiles` (danh sách file cho phép thay đổi) và `ignoreUntracked`.
   - Hàm `isRepoClean(repoPath, options)`: Trả về `boolean` kiểm tra repo có sạch hay không.
   - Hàm `checkRepoClean(repoPath, options)`:
     - Khi repo bẩn (có thay đổi staged, unstaged, untracked, deleted không nằm trong `allowedFiles`): lập tức ném `AppError` với mã `REPO_DIRTY` và thông báo chi tiết danh sách file vi phạm, kèm context cấu trúc `{ repoPath, dirtyCount, dirtyFiles, raw }`.
     - Khi repo sạch: trả về `{ isClean: true, files: [], raw }`.
   - Re-export toàn bộ module qua `packages/shared/src/index.ts`.

2. **Git Adapter trong Orchestrator (`apps/orchestrator/src/adapters/git.ts`)**:
   - Định nghĩa adapter Git theo đúng cấu trúc chuẩn của `SKILL-node-typescript.md`.
   - Re-export `checkRepoClean`, `getRepoStatus`, `isRepoClean`, `parseGitPorcelain` và các kiểu dữ liệu liên quan.
   - Re-export qua `apps/orchestrator/src/index.ts`.

3. **Kiểm thử tự động**:
   - `packages/shared/src/__tests__/git.test.ts` (12 tests):
     - Phân tích cú pháp porcelain (rỗng, staged, unstaged, cả hai, deleted, rename, tên file có khoảng trắng trong ngoặc kép).
     - Xử lý các tình huống lỗi: thư mục không tồn tại (`PATH_NOT_FOUND`), file không phải thư mục (`NOT_A_DIRECTORY`), thư mục không phải git repository (`NOT_A_GIT_REPO`).
     - Repo git rỗng sạch và repo có commit sạch.
     - Repo bẩn do file untracked, uncommitted modification.
     - Kiểm thử tùy chọn `allowedFiles` và `ignoreUntracked`.
   - `test/fnd-006.test.ts` (7 tests): Kiểm thử nghiệm thu cấp độ root:
     - Repo bẩn do untracked file → trả lỗi `REPO_DIRTY`.
     - Repo bẩn do modified file (unstaged) → trả lỗi `REPO_DIRTY`.
     - Repo bẩn do staged change chưa commit → trả lỗi `REPO_DIRTY`.
     - Repo bẩn do xóa file chưa commit → trả lỗi `REPO_DIRTY`.
     - **Không ghi đè**: khi repo bẩn, thao tác bảo vệ bởi `checkRepoClean` bị chặn, không ghi đè hay làm mất dữ liệu file.
     - Repo sạch → `checkRepoClean` thành công, cho phép thao tác an toàn.
     - Hoạt động đồng bộ qua export từ orchestrator adapters.
