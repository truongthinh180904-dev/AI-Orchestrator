## 1. Kết Quả Thực Hiện

### 1.1. Bảng Khóa Agent & Tầng Database (`packages/db/migrations/002_agent_lock.sql` & `AgentLockRepository`)
- Bổ sung migration chuẩn hóa có đánh số `002_agent_lock.sql` theo đúng `SKILL-sqlite.md`:
  - Bảng `agent_locks`: `id` (PK), `task_id` (FK cascade sang `tasks`), `run_id` (FK sang `runs`), `acquired_at` (TEXT ISO-8601), `owner_pid` (INTEGER), `metadata` (TEXT JSON).
  - Chỉ mục `idx_agent_locks_task_id` trên `agent_locks(task_id)`.
- Triển khai `AgentLockRepository` (`packages/db/src/repositories/agent-lock-repository.ts`):
  - `acquire(input)`: Thực hiện trong SQLite transaction để kiểm tra lock và insert row; ném lỗi `AppError('AGENT_LOCK_HELD')` nếu khóa đang bị chiếm giữ.
  - `release(id, taskId?)`: Xóa bản ghi lock theo `id` và tùy chọn `task_id`.
  - `updateRunId(id, runId)`: Cập nhật `run_id` của tiến trình worker vào bản ghi lock.
  - `getCurrentLock(id)`: Truy vấn thông tin lock hiện tại, parse qua Zod `AgentLockSchema`.
  - `isLocked(id)`: Kiểm tra boolean nhanh sự tồn tại của lock.
  - `forceRelease(id)`: Cưỡng bức giải phóng khóa.

### 1.2. Bộ Điều Phối Tác Vụ `TaskScheduler` (`apps/orchestrator/src/services/task-scheduler.ts`)
- **Nguyên tắc "Concurrency: Tối đa 1 coding process tại một thời điểm"**:
  - `acquireNextTask(options)`:
    - Bọc toàn bộ thao tác trong SQLite Transaction chế độ tức thời (`tx.immediate()`), bảo đảm tính nguyên tử (atomicity) tuyệt đối ở mức database engine.
    - Kiểm tra `agent_locks`: Nếu có lock đang active (và task liên kết đang `RUNNING` hoặc `VERIFYING`), từ chối lập tức với lý do `LOCK_HELD`.
    - Tự động phát hiện và dọn dẹp stale lock nếu task liên kết đã kết thúc (`DONE`, `FAILED`, `CANCELLED`).
    - Kiểm tra bảng `tasks`: Nếu có bất kỳ task nào trong hệ thống đang `RUNNING` hoặc `VERIFYING`, từ chối với lý do `CONCURRENCY_LIMIT_EXCEEDED`.
    - Kiểm tra bảng `runs`: Nếu có run nào đang `RUNNING`, từ chối với lý do `ACTIVE_RUN_EXISTS`.
    - Gọi `DependencyResolver` (`findReadyTasks` với candidateStatuses `['READY', 'TODO']`, sắp xếp tất định: `priority DESC`, `created_at ASC`, `id ASC`).
    - Chuyển trạng thái task sang `RUNNING` (tự tăng `attempts = attempts + 1`, cập nhật `updated_at`).
    - Ghi bản ghi vào `agent_locks`.
- **Bước điều phối `step(options)`**:
  - Kiểm tra trạng thái pause: nếu scheduler đang tạm dừng, trả về `{ executed: false, reason: 'SCHEDULER_PAUSED' }`.
  - Thực thi `acquireNextTask()`.
  - Khởi chạy worker qua `RunService.startRun({ taskId, skipLockCheck: true })`.
  - Cập nhật `runId` vào lock và chờ tiến trình hoàn tất (`execution.waitForCompletion()`).
  - Cập nhật state machine task chuẩn ORC-001:
    - Exit 0 / `SUCCESS` → chuyển `RUNNING → VERIFYING` → nếu `autoVerify: true` (mặc định) → chuyển `VERIFYING → DONE`.
    - `CANCELLED` → chuyển `RUNNING → CANCELLED`.
    - Exit code khác 0 / `ERROR` / `TIMEOUT` → chuyển `RUNNING → FAILED`.
  - Tự động giải phóng lock trong khối `finally` đảm bảo không bao giờ rò rỉ khóa.
- **Vòng lặp tuần tự `runUntilEmpty(options)`**:
  - Chạy tuần tự từng task một cho đến khi không còn task sẵn sàng hoặc có lệnh dừng/tạm dừng.
- **Các thao tác điều khiển vận hành**:
  - `pause()`: Tạm dừng scheduler.
  - `resume()`: Tiếp tục điều phối.
  - `stop(cancelActive)`: Dừng scheduler và hủy run đang chạy (nếu có).
  - `getStatus()`: Trả về trạng thái thời gian thực (`isRunning`, `isPaused`, `activeLock`, `activeTaskId`, `activeRunId`, `readyTasksCount`).
  - `releaseLock()`: Cưỡng bức giải phóng khóa.

### 1.3. Đồng Bộ Tầng `RunService` (`apps/orchestrator/src/services/run-service.ts`)
- Kiểm tra tính độc quyền thực thi trong `startRun`:
  - Nếu `!input.skipLockCheck`, kiểm tra `executionManager.listRunning()` và `lockRepo.getCurrentLock()`.
  - Nếu có tiến trình worker đang chạy, ném ngay `AppError('CONCURRENCY_LIMIT_EXCEEDED')` hoặc `AppError('AGENT_LOCK_HELD')` (Fastify map sang HTTP 409 Conflict).
  - Tự động gắn listener `execution.handle.on('close')` để giải phóng lock khi tiến trình kết thúc.
  - Giải phóng lock khi gọi `stopRun`.

### 1.4. Tầng REST API Scheduler (`apps/orchestrator/src/routes/scheduler.ts`)
- `POST /scheduler/next` & `POST /api/scheduler/next`: Kích hoạt bước điều phối tiếp theo.
- `GET /scheduler/status` & `GET /api/scheduler/status`: Lấy trạng thái scheduler thời gian thực.
- `POST /scheduler/start` & `POST /api/scheduler/start`: Khởi chạy sequential loop chạy ngầm.
- `POST /scheduler/stop` & `POST /api/scheduler/stop`: Dừng scheduler và hủy run active.
- `POST /scheduler/pause` & `POST /api/scheduler/pause`: Tạm dừng scheduler.
- `POST /scheduler/resume` & `POST /api/scheduler/resume`: Tiếp tục scheduler.
- `POST /scheduler/release-lock` & `POST /api/scheduler/release-lock`: Cưỡng bức giải phóng khóa.
