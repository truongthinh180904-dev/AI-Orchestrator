## 1. Kết Quả Thực Hiện

### 1.1. GitHub CLI Engine An Toàn (`packages/shared/src/gh.ts`)
- **`ghPrCreate(options)`**:
  - Thực thi tạo Pull Request bằng `child_process.spawn('gh', ['pr', 'create', ...args])` an toàn, tuyệt đối không dùng shell injection hay `exec`.
  - Tham số dòng lệnh: `--base <base>`, `--head <branch>`, `--title <title>`, `--body-file <reports/<feature>.md>` (hoặc `--body <content>`), `--draft` (tùy chọn).
  - Tự động bóc tách URL Pull Request và số hiệu PR (`pr_number`) từ output của `gh`.
  - Tính lũy đẳng (Idempotency): Tự động phát hiện trường hợp PR đã tồn tại (`GH_PR_ALREADY_EXISTS`), trích xuất PR URL hiện có và trả về an toàn (`isExisting: true`) khi có cờ `allowExisting: true` (mặc định).
  - Hỗ trợ cơ chế retry tự động với exponential backoff cho lỗi mạng / kết nối tạm thời (`GH_NETWORK_ERROR`, mặc định 2 lần thử lại).
  - Fail-fast ngay lập tức khi gặp lỗi xác thực hoặc không tìm thấy binary `gh` (`GH_AUTH_FAILED`, `GH_NOT_FOUND`).
- **`sanitizeGhOutput(text)`**:
  - Che giấu và loại bỏ toàn bộ token, credentials (`[REDACTED_GH_TOKEN]`, `[REDACTED_GH_PAT]`, `[REDACTED_CREDENTIALS]`, `[REDACTED_TOKEN]`) khỏi log và lỗi (GitHub PAT classic `ghp_*`, fine-grained `github_pat_*`, OAuth `gho_*`, Bearer tokens, URL credentials).
- **`ghPrView(branchOrNumber, options)`**:
  - Truy vấn thông tin PR qua `gh pr view --json url,number,state,title,headRefName,baseRefName`.

### 1.2. Release Models & Report Generator (`packages/shared/src/models/release.ts`)
- **`CreateFeaturePrInputSchema`**:
  - Tham số tạo PR: `title`, `body`, `base_branch`, `head_branch`, `draft`, `repo_path`, `save_report_file`, `report_file_path`, `max_retries`, `retry_delay_ms`, `allow_existing`.
- **`CreateFeaturePrResultSchema`**:
  - Kết quả tạo PR: `release_id`, `feature_id`, `branch`, `base_branch`, `commit_sha` (40 ký tự hex), `pr_url` (valid URL), `pr_number`, `status: 'READY_FOR_REVIEW'`, `quality_report_id`, `quality_report_path`, `created_at`.
- **`FeatureReleaseReportResultSchema`**:
  - Kết quả truy vấn báo cáo phát hành: `feature_id`, `feature_name`, `release_id`, `branch`, `base_branch`, `commit_sha`, `pr_url`, `status`, `report_content`, `report_path`, `report_id`, `generated_at`.
- **`generateFeatureReleaseReportMarkdown(options)`**:
  - Sinh nội dung báo cáo phát hành (Release Report) toàn diện định dạng Markdown GitHub-flavored:
    - Metadata: Feature ID, Feature Name, Trạng thái `READY_FOR_REVIEW` (Chờ người duyệt), Base branch, Release branch, Commit SHA, PR URL, Generated At.
    - Component Tasks table: thứ tự thực thi topo, Task ID, Title, Status (DONE), Is Required, Phase.
    - Quality Gate & Compliance summary: CLI execution, Quality Commands, Task Scope, Code Review, Security Check.
    - Integration test results (nếu có).
    - Review & Sign-Off Checklist: Đánh dấu sẵn sàng bàn giao và chờ người duyệt (human approval) trước khi merge vào nhánh chính.

### 1.3. FeatureReleaseService & FeatureService (`apps/orchestrator/src/services/`)
- **`createFeaturePr(featureId, input)`**:
  - Kiểm tra feature tồn tại (`FEATURE_NOT_FOUND`) và release record tồn tại (`FEATURE_BRANCH_NOT_FOUND`).
  - Đảm bảo branch đã commit (`FEATURE_NOT_COMMITTED` nếu chưa commit hoặc đang ở `BRANCH_CREATED`).
  - Đảm bảo branch đã push lên remote (`FEATURE_NOT_PUSHED` nếu chưa push).
  - Tự động sinh báo cáo release và lưu:
    1. Ghi file báo cáo Markdown trên đĩa: `reports/<feature-id>.md` (theo quy chuẩn `SKILL-git-release.md`).
    2. Ghi bản ghi báo cáo vào SQLite DB: bảng `reports` (`kind: 'feature_release'`).
  - Thực thi tạo PR qua `ghPrCreate`.
  - Cập nhật SQLite DB (`feature_releases`): lưu `pr_url`, `commit_sha`, chuyển trạng thái `status = 'READY_FOR_REVIEW'`, lưu `metadata` (`quality_report_id`, `quality_report_path`, `pr_number`, `pr_title`).
  - Ghi JSON structured log với thông tin release an toàn, không chứa secret.
- **`getFeatureReleaseReport(featureId)`**:
  - Truy vấn báo cáo phát hành từ SQLite DB hoặc file trên đĩa hoặc tự động sinh theo manifest hiện hành.
- **Expose qua `FeatureService`**: Cung cấp `createFeaturePr` và `getFeatureReleaseReport`.

### 1.4. REST API Endpoints & Server Integration (`apps/orchestrator/src/routes/features.ts`, `server.ts`)
- `POST /features/:id/pr` & `POST /api/features/:id/pr`: Tạo GitHub PR và sinh báo cáo phát hành (HTTP 201).
- `GET /features/:id/pr` & `GET /api/features/:id/pr`: Lấy thông tin PR của feature (HTTP 200, 404 nếu chưa tạo).
- `GET /features/:id/release-report` & `GET /api/features/:id/release-report`: Lấy nội dung báo cáo phát hành của feature (HTTP 200).
- Centralized Error Handling: xử lý `GH_NOT_FOUND` (500), `GH_AUTH_FAILED` (401), `GH_PR_ALREADY_EXISTS` (409), `GH_NETWORK_ERROR` (504), `GH_COMMAND_FAILED` (500), `FEATURE_NOT_PUSHED` (400), `FEATURE_NOT_COMMITTED` (400), `PR_NOT_FOUND` (404).
