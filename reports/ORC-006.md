## 1. Kết Quả Thực Hiện

### 1.1. Mô Hình Dữ Liệu & Zod Schemas (`packages/shared/src/models/plan.ts`)
- **`PlanTaskSchema`**:
  - `id`: Định danh duy nhất của task trong kế hoạch (string, min 1).
  - `title`: Tên task (string, min 1).
  - `description`: Mô tả chi tiết (string | null).
  - `scope_files`: Danh sách các file trong repo mà task sẽ chỉnh sửa/tạo mới (`z.array(z.string().min(1)).min(1)` - bắt buộc có ít nhất 1 file trong phạm vi).
  - `acceptance_criteria`: Danh sách tiêu chí nghiệm thu cụ thể (`z.array(z.string().min(1)).min(1)` - bắt buộc có ít nhất 1 tiêu chí).
  - `dependencies`: Mảng mã task phụ thuộc (`z.array(z.string().min(1))`, mặc định `[]`).
  - `test_commands`: Các lệnh kiểm thử dùng để xác thực task (`z.array(z.string().min(1))`, mặc định `[]`).
  - `priority`: Độ ưu tiên (integer, mặc định 0).
  - `timeout_minutes`: Thời gian chạy tối đa (integer, mặc định 30).
  - `worker_type`: Loại worker thực thi (string, mặc định `'agy'`).
- **`PlanTaskInputSchema`**:
  - Chuẩn hóa linh hoạt các trường tương đương từ output của LLM/AGY (`files` hoặc `scope` -> `scope_files`, `acceptance` -> `acceptance_criteria`), đồng thời đảm bảo kết quả chuyển đổi tuân thủ nghiêm ngặt `PlanTask`.
- **`PlanContentSchema`**:
  - Cấu trúc nội dung do Planner AGY sinh ra gồm `title`, `description`, và mảng `tasks` (tối thiểu 1 task).
- **`PlanSchema`**:
  - Bản ghi Plan hoàn chỉnh trong hệ thống: `id`, `feature_id`, `title`, `description`, `repository`, `status`, `tasks`, `raw_output`, `created_at`, `updated_at`, `approved_at`, `approved_by`, `rejection_reason`.
  - Hỗ trợ các trạng thái vòng đời: `'DRAFT' | 'PENDING_APPROVAL' | 'APPROVED' | 'REJECTED' | 'EXECUTING' | 'COMPLETED' | 'FAILED'`.
- **`extractJsonPlan(rawText)`**:
  - Hàm bóc tách JSON an toàn: hỗ trợ markdown code fence (` ```json ... ``` `), JSON thuần (raw JSON), hoặc chuỗi chứa văn bản đàm thoại bao quanh.
- **`validatePlanTasksGraph(tasks)`**:
  - Kiểm tra tính hợp lệ của đồ thị phụ thuộc giữa các task:
    1. Kiểm tra tính duy nhất của mã task ID trong plan.
    2. Kiểm tra mọi dependency đều tham chiếu đến task ID có thực trong plan.
    3. Ngăn chặn tự phụ thuộc vào chính mình (self-dependency).
    4. Sử dụng `DependencyGraph` để phát hiện và ngăn chặn chu trình phụ thuộc (circular dependency).

### 1.2. Migration 004 & Cơ Sở Dữ Liệu SQLite (`packages/db/migrations/004_plans.sql`)
- Khởi tạo bảng `plans` lưu trữ kế hoạch thực thi:
  - `id TEXT PRIMARY KEY`: Định danh kế hoạch (UUID có tiền tố `plan_`).
  - `feature_id TEXT REFERENCES features(id) ON DELETE SET NULL`: Khóa ngoại liên kết feature tương ứng nếu có.
  - `title TEXT NOT NULL`: Tiêu đề kế hoạch.
  - `description TEXT`: Mô tả mục tiêu kế hoạch.
  - `repository TEXT NOT NULL DEFAULT '.'`: Đường dẫn repository mục tiêu.
  - `status TEXT NOT NULL DEFAULT 'PENDING_APPROVAL'`: Trạng thái duyệt kế hoạch.
  - `tasks TEXT NOT NULL DEFAULT '[]'`: Mảng JSON lưu trữ các task của kế hoạch.
  - `raw_output TEXT`: Lưu trữ output thô từ AGY phục vụ truy vết/kiểm toán.
  - `created_at TEXT NOT NULL`, `updated_at TEXT NOT NULL`: Mốc thời gian ISO-8601 UTC.
  - `approved_at TEXT`, `approved_by TEXT`, `rejection_reason TEXT`: Trường phục vụ quy trình review & approve (ORC-007).
  - Chỉ mục tối ưu hóa: `idx_plans_status`, `idx_plans_feature_id`.

### 1.3. Lớp Repository (`packages/db/src/repositories/plan-repository.ts`)
- **`PlanRepository`**:
  - `create(input)`: Tạo kế hoạch mới với kiểm tra toàn vẹn schema Zod và khóa ngoại.
  - `findById(id)`: Lấy thông tin kế hoạch kèm mảng tasks đã deserialize và validate.
  - `findAll(filter)`: Lọc danh sách kế hoạch theo `status`, `feature_id`, `repository`.
  - `update(id, updates)`: Cập nhật thông tin kế hoạch và trạng thái phê duyệt.
  - `delete(id)`: Xóa kế hoạch.
  - `count(filter)`: Đếm số lượng kế hoạch theo bộ lọc.

### 1.4. Tầng Dịch Vụ Planner (`apps/orchestrator/src/services/planner-service.ts`)
- **`PlannerService`**:
  - `buildPlannerPrompt(goal, options)`: Sinh prompt yêu cầu AGY phân tích repository và tạo kế hoạch JSON với đầy đủ cấu trúc: `id`, `title`, `description`, `scope_files`, `acceptance_criteria`, `dependencies`.
  - `generatePlan(input)`:
    - Kiểm tra đường dẫn repository tồn tại và hợp lệ (`fs.existsSync`, `fs.statSync`).
    - Xác thực qua `RepositoryRegistry` (nếu có cấu hình).
    - Tạo lệnh `AgentCommand` và khởi chạy tiến trình AGY qua `ProcessAdapter.spawn(...)` (không dùng shell động).
    - Thu thập luồng stdout, stderr và giám sát timeout watchdog.
    - Bóc tách JSON qua `extractJsonPlan`.
    - Kiểm định cấu trúc schema Zod qua `PlanContentSchema`.
    - Kiểm định tính phi chu trình (DAG) qua `validatePlanTasksGraph`.
    - Lưu trữ kế hoạch vào SQLite với trạng thái `PENDING_APPROVAL`.
  - `parseAndValidatePlan(rawOutput, metadata)`: Hỗ trợ bóc tách, xác thực và lưu trữ trực tiếp từ chuỗi JSON thô mà không cần gọi tiến trình ngoài.
  - `getPlan(id)`, `listPlans(filter)`, `deletePlan(id)`: Các phương thức quản lý kế hoạch.

### 1.5. Tầng REST API (`apps/orchestrator/src/routes/plans.ts`)
- `POST /plans/generate` & `POST /api/plans/generate`: Khởi chạy AGY sinh kế hoạch từ repo, xác thực qua Zod, lưu DB và trả về 201 Created.
- `POST /plans/validate` & `POST /api/plans/validate`: Xác thực trực tiếp chuỗi JSON kế hoạch qua Zod và trả về 200 OK.
- `GET /plans/:id` & `GET /api/plans/:id`: Tra cứu chi tiết kế hoạch theo ID (404 nếu không tồn tại).
- `GET /plans` & `GET /api/plans`: Liệt kê danh sách kế hoạch theo bộ lọc.
- `DELETE /plans/:id` & `DELETE /api/plans/:id`: Xóa kế hoạch.
