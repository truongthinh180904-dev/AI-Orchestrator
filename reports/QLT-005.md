## 1. Kết Quả Thực Hiện

### 1.1. Data Model & Zod Schemas (`packages/shared/src/models/security-check.ts`)
- **`AuditVulnerabilitySchema` & `AuditCountsSchema`**: Định nghĩa cấu trúc lỗ hổng dependency bóc tách từ audit với 5 mức severity quy chuẩn (`info`, `low`, `moderate`, `high`, `critical`), CWE, module name, vulnerable/patched versions, và danh sách paths.
- **`AuditResultSchema`**: Tổng hợp kết quả audit gồm `passed` (tuân thủ rule SKILL-testing: "audit không có lỗ hổng high+"), `command`, `exit_code`, `stdout`, `stderr`, `duration_ms`, `vulnerabilities`, `counts`, `highOrCriticalCount`, và `summary`.
- **`SecretFindingSchema`**: Xác thực thông tin secret tìm thấy (`rule_id`, `description`, `file`, `line`, `match_preview`, `secret_hash`, `commit`, `author`, `date`).
- **`SecretScanResultSchema`**: Cấu trúc kết quả quét secret gồm `passed`, `scanner` (`gitleaks` | `builtin` | `both`), `findings`, `total_findings`, `files_scanned`, `summary`.
- **`SecurityCheckResultSchema`**: Cấu trúc tổng hợp Security Check toàn diện gồm `id`, `task_id`, `run_id`, `repo_path`, `passed` (true nếu cả audit và secret scan đều pass), `audit`, `secrets`, `summary`, `started_at`, `finished_at`, `duration_ms`.
- **Bảo mật tuyệt đối (Rule 3 AGENTS.md)**:
  - `maskSecret(secret)`: Tự động mặt nạ hóa chuỗi secret (chỉ giữ ký tự đầu/cuối, thay thế thân bằng `*`), triệt để ngăn chặn rò rỉ secret vào log/DB/report.
  - `hashSecret(secret)`: Băm SHA-256 để định danh và chống trùng lặp mà không cần lưu plaintext.

### 1.2. Parsers & Scanners (`packages/shared/src/security/`)
- **`parsePnpmAuditOutput` (`audit-parser.ts`)**:
  - Bóc tách JSON tin cậy từ `pnpm audit --json` (và tương thích npm audit).
  - Trích xuất toàn bộ dictionary advisories hoặc mảng vulnerabilities.
  - Kiểm định Quality Gate: Đánh dấu `passed: false` khi có bất kỳ lỗ hổng mức `high` hoặc `critical`.
- **`SecretScanner` (`secret-scanner.ts`)**:
  - `isGitleaksAvailable`: Tự động thăm dò sự hiện diện của CLI `gitleaks` trên hệ thống.
  - `parseGitleaksJson`: Bóc tách report JSON của Gitleaks khi gitleaks được sử dụng, tự động che giấu mọi match.
  - Built-in regex rule set: Quét chính xác AWS Access Keys (`AKIA...`), Unencrypted Private Keys (`-----BEGIN ... PRIVATE KEY-----`), GitHub PATs (`ghp_...`, `github_pat_...`), Slack Tokens (`xoxb-...`), AI Service Keys (`sk-...`, `sk-ant-...`), JWT tokens, và gán cứng credential/password.
  - `isIgnoredScanPath`: Tự động loại trừ các thư mục và file không cần quét (`.git`, `node_modules`, `dist`, lockfiles, binary files, file ảnh).
  - `scanDirectoryForSecrets`: Quét an toàn toàn bộ repository trên đĩa.
  - `scanTextForSecrets`: Quét trực tiếp nội dung diff git hoặc chuỗi văn bản.

### 1.3. Migration 009 & Database Repository (`packages/db/migrations/009_security_checks.sql`)
- Khởi tạo bảng `security_checks` và `secret_findings` trong SQLite:
  - `security_checks`: `id`, `task_id`, `run_id`, `repo_path`, `passed`, `audit_passed`, `secret_passed`, `audit_high_critical_count`, `secret_findings_count`, `audit_summary`, `secret_summary`, `raw_details`, `duration_ms`, `created_at`.
  - `secret_findings`: `id`, `security_check_id`, `task_id`, `rule_id`, `description`, `file`, `line`, `match_preview`, `secret_hash`, `created_at`.
  - Khóa ngoại liên kết `tasks(id)` và `runs(id)` với `ON DELETE CASCADE`.
  - Các chỉ mục tối ưu: `idx_security_checks_task_id`, `idx_security_checks_run_id`, `idx_security_checks_passed`, `idx_security_checks_created_at`, `idx_secret_findings_security_check_id`, `idx_secret_findings_task_id`.
- **`SecurityCheckRepository` (`packages/db/src/repositories/security-check-repository.ts`)**:
  - `create(input, findings)`: Lưu trữ bản ghi security check và các secret findings trong transaction SQLite an toàn.
  - Tự động tạo bản ghi kiểm toán trong bảng `reports` (`kind: 'security_check'`) khi có `run_id`.
  - `findById`, `findByTaskId`, `findByRunId`, `findSecretFindingsByCheckId`, `findSecretFindingsByTaskId`.
  - `find` và `count` hỗ trợ lọc theo `task_id`, `run_id`, `passed`, phân trang `limit`/`offset`.

### 1.4. Security Check Service (`apps/orchestrator/src/services/security-check-service.ts`)
- **`SecurityCheckService`**:
  - `runAudit(options)`: Chạy `pnpm audit --json` qua `ProcessAdapter` (không dùng shell động), bóc tách kết quả, lưu vào `quality_command_records`.
  - `runSecretScan(options)`: Kiểm tra gitleaks CLI; chạy gitleaks nếu có hoặc fallback sang built-in regex scanner; hỗ trợ quét diff trực tiếp.
  - `runSecurityCheck(options)`: Thực hiện toàn bộ quy trình kiểm tra bảo mật (audit + secrets), lưu trữ kết quả thật vào SQLite.
  - `checkTask(taskId, options)`: Tự động tra cứu task, phân giải repository path và thực thi kiểm tra bảo mật gắn với task.

### 1.5. REST API Endpoints (`apps/orchestrator/src/routes/quality.ts`)
- `POST /api/quality/security-check`: Chạy kiểm tra bảo mật tổng hợp (audit + secret scan).
- `GET /api/quality/security-checks`: Truy vấn danh sách security checks có lọc và phân trang.
- `GET /api/quality/security-checks/:id`: Lấy chi tiết security check theo ID.
- `GET /api/quality/security-checks/:id/secrets`: Lấy danh sách secret findings của security check.
- `GET /api/tasks/:id/security-checks`: Lấy danh sách security checks gắn với task.
- `POST /api/tasks/:id/security-check`: Kích hoạt security check cho task cụ thể.
- `POST /api/quality/audit`: Chạy kiểm tra dependency audit độc lập.
- `POST /api/quality/secrets/scan`: Chạy quét secret độc lập (trên repo hoặc git diff).
