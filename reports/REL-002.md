## 1. Kết Quả Thực Hiện

### 1.1. Data Models & Zod Schemas (`packages/shared/src/models/release.ts`)
- **`FeatureReleaseCheckRuleStatusSchema`**: Các trạng thái đánh giá rule: `'PASSED' | 'FAILED' | 'SKIPPED' | 'WARNING'`.
- **`FeatureReleaseCheckRuleSchema`**:
  - `rule_id`: Mã định danh rule (`NON_EMPTY_FEATURE`, `NO_MISSING_TASKS`, `REQUIRED_TASKS_COMPLETED`, `QUALITY_GATE_COMPLIANCE`, `INTEGRATION_TESTS_PASSED`).
  - `name`: Tên quy tắc kiểm tra.
  - `passed`: Kết quả boolean.
  - `status`: Trạng thái chi tiết.
  - `message`: Thông báo đánh giá trực quan.
  - `details`: Metadata chi tiết (danh sách task thiếu, task chưa xong, lỗi Quality Gate, ...).
- **`FeatureIntegrationTestRecordSchema`**:
  - `command`: Lệnh kiểm thử tích hợp thực thi.
  - `status`: `'SUCCESS' | 'FAILURE' | 'TIMEOUT' | 'SKIPPED' | 'ERROR'`.
  - `exit_code`: Mã thoát tiến trình (exit code).
  - `stdout`, `stderr`: Luồng đầu ra chuẩn.
  - `duration_ms`: Thời lượng thực thi từng lệnh.
- **`FeatureReleasePolicyOptionsSchema`**:
  - `require_all_required_done`: Mặc định `true` — bắt buộc mọi task bắt buộc đạt `DONE`.
  - `require_no_missing_tasks`: Mặc định `true` — bắt buộc không có task bắt buộc nào bị thiếu trong DB.
  - `require_non_empty`: Mặc định `true` — chặn release feature rỗng không có task.
  - `require_quality_gate_passed`: Mặc định `true` — bắt buộc mọi task bắt buộc phải vượt qua Quality Gate (QLT-007).
  - `require_integration_tests`: Cấu hình yêu cầu bắt buộc chạy integration test.
  - `stop_on_first_integration_failure`: Mặc định `true`.
- **`FeatureReleaseCheckResultSchema`**:
  - `feature_id`, `feature_name`: Thông tin định danh feature.
  - `can_release`: Cờ boolean xác định feature sẵn sàng release hay bị chặn.
  - `status`: `'READY' | 'BLOCKED'`.
  - `blocking_reasons`: Danh sách các lý do cụ thể khiến feature bị chặn phát hành.
  - `rule_evaluations`: Mảng kết quả đánh giá 5 quy tắc độc lập.
  - `task_summary`: Thống kê tiến độ các task.
  - `manifest`: Manifest chi tiết task thành phần từ REL-001.
  - `integration_test_results`: Mảng kết quả thực thi integration test.
  - `checked_at`: Thời điểm kiểm tra.
- **`formatFeatureReleaseCheckMarkdownReport`**: Sinh báo cáo nghiệm thu Markdown chuẩn GFM kèm bảng rules, blocking reasons và kết quả integration tests.

### 1.2. Mở rộng ReportRepository (`packages/db/src/repositories/report-repository.ts`)
- Thêm `findByKind(kind: string)` và `findAll(filter?: ReportFilter)` để truy vấn lịch sử báo cáo kiểm tra release (`kind: 'feature_release_check'`) và kiểm thử tích hợp (`kind: 'feature_integration_test'`).

### 1.3. FeatureReleaseService (`apps/orchestrator/src/services/feature-release-service.ts`)
- **`checkReleaseReadiness(featureId, options)`**:
  - Đánh giá toàn diện 5 quy tắc release:
    1. **NON_EMPTY_FEATURE**: Chặn release nếu feature không có task nào.
    2. **NO_MISSING_TASKS**: Chặn release nếu có bất kỳ task bắt buộc nào được khai báo nhưng chưa tồn tại trong DB (`missing_task_ids`).
    3. **REQUIRED_TASKS_COMPLETED**: Chặn release nếu có bất kỳ task bắt buộc nào chưa đạt trạng thái `DONE`.
    4. **QUALITY_GATE_COMPLIANCE**: Tích hợp với `QualityGateRepository` (QLT-007), chặn release nếu task bắt buộc chưa có bản ghi Quality Gate hoặc kết quả đánh giá gần nhất bị `FAILED`.
    5. **INTEGRATION_TESTS_PASSED**: Thực thi các lệnh kiểm thử tích hợp qua `ProcessAdapter` (không dùng shell), bắt lỗi và exit code; chặn release nếu bất kỳ lệnh nào thất bại.
  - Thu thập toàn bộ lý do chặn vào `blocking_reasons`, thiết lập `status: 'BLOCKED'` và `can_release: false` nếu vi phạm.
  - Tự động lưu vết báo cáo Markdown vào bảng `reports` (`kind: 'feature_release_check'`).
- **`assertCanRelease(featureId, options)`**:
  - Gọi `checkReleaseReadiness`. Nếu `!result.can_release`, lập tức ném `AppError('FEATURE_RELEASE_BLOCKED')` kèm danh sách lý do cụ thể và đối tượng kết quả.
- **`runIntegrationTests(featureId, options)`**:
  - Phân tách an toàn lệnh kiểm thử qua `parseCommandLine`, chạy tuần tự qua `ProcessAdapter.spawn` (tuân thủ `shell: false`), thu thập stdout/stderr, xử lý timeout an toàn, và lưu báo cáo vào bảng `reports` (`kind: 'feature_integration_test'`).

### 1.4. REST API Endpoints (`apps/orchestrator/src/routes/features.ts`)
- `GET /features/:id/release-check` & `GET /api/features/:id/release-check`: Kiểm tra điều kiện release của feature.
- `POST /features/:id/release-check` & `POST /api/features/:id/release-check`: Kiểm tra điều kiện release với tùy chọn thực thi integration test và cờ `assert: true` (trả về HTTP 422 khi bị chặn).
- `POST /features/:id/integration-tests` & `POST /api/features/:id/integration-tests`: Chạy các lệnh kiểm thử tích hợp của feature.

## 2. Tiêu Chí Nghiệm Thu & Bằng Chứng

### Tiêu chí cốt lõi: Thiếu task → chặn
- [x] **Nghiệm thu 1: Thiếu task bắt buộc trong DB -> Chặn phát hành**
  - Khi feature có task trong `required_tasks` không tồn tại trong DB, hệ thống đánh dấu rule `NO_MISSING_TASKS` FAILED, `can_release: false`, `status: 'BLOCKED'`, ghi rõ tên task thiếu, và ném lỗi `AppError('FEATURE_RELEASE_BLOCKED')` khi gọi `assertCanRelease`.
  - *Bằng chứng*: `test/rel-002.test.ts` (Nghiệm thu 1) & `apps/orchestrator/src/__tests__/feature-release-service.test.ts` (Tiêu chí 1).
- [x] **Nghiệm thu 2: Task bắt buộc chưa đạt trạng thái DONE -> Chặn phát hành**
  - Khi task bắt buộc còn ở trạng thái `TODO`, `RUNNING`, `FAILED`, `BLOCKED`, rule `REQUIRED_TASKS_COMPLETED` bị FAILED, feature bị chặn release.
  - *Bằng chứng*: `test/rel-002.test.ts` (Nghiệm thu 2) & `apps/orchestrator/src/__tests__/feature-release-service.test.ts` (Tiêu chí 2).
- [x] **Nghiệm thu 3: Task bắt buộc chưa vượt qua Quality Gate (QLT-007) -> Chặn phát hành**
  - Dù task đã `DONE`, nếu chưa có bản ghi Quality Gate hoặc Quality Gate gần nhất bị `FAILED`, rule `QUALITY_GATE_COMPLIANCE` bị FAILED và feature bị chặn release.
  - *Bằng chứng*: `test/rel-002.test.ts` (Nghiệm thu 3) & `apps/orchestrator/src/__tests__/feature-release-service.test.ts` (Tiêu chí 3).
- [x] **Nghiệm thu 4: Integration test của feature thất bại -> Chặn phát hành**
  - Khi thực thi kiểm thử tích hợp mà có lệnh trả về exit code khác 0, rule `INTEGRATION_TESTS_PASSED` bị FAILED, lưu chi tiết exit code và stderr, chặn release.
  - *Bằng chứng*: `test/rel-002.test.ts` (Nghiệm thu 4) & `apps/orchestrator/src/__tests__/feature-release-service.test.ts` (Tiêu chí 4).
- [x] **Nghiệm thu 5: Feature rỗng không có task -> Chặn phát hành**
  - Khi feature không có bất kỳ task thành phần nào, rule `NON_EMPTY_FEATURE` bị FAILED, ngăn chặn việc release một feature rỗng.
  - *Bằng chứng*: `test/rel-002.test.ts` (Nghiệm thu 5) & `apps/orchestrator/src/__tests__/feature-release-service.test.ts` (Tiêu chí 5).
- [x] **Nghiệm thu 6: Đủ task bắt buộc DONE + Quality Gate PASS + Integration test PASS -> SẴN SÀNG RELEASE**
  - Khi 100% task bắt buộc tồn tại, đều `DONE`, đều có Quality Gate PASS, và toàn bộ integration tests thành công (exit code 0), feature đạt `can_release: true`, `status: 'READY'`, không có blocking reasons.
  - *Bằng chứng*: `test/rel-002.test.ts` (Nghiệm thu 6) & `apps/orchestrator/src/__tests__/feature-release-service.test.ts` (Tiêu chí 6).
- [x] **Nghiệm thu 7: Lưu vết báo cáo vào bảng reports trong SQLite**
  - Toàn bộ kết quả release check và integration test được lưu trữ vào bảng `reports` (`kind: 'feature_release_check'` và `kind: 'feature_integration_test'`).
  - *Bằng chứng*: `test/rel-002.test.ts` (Nghiệm thu 7) & `apps/orchestrator/src/__tests__/feature-release-service.test.ts` (Tiêu chí 7).
- [x] **Nghiệm thu 8: REST API endpoints kiểm tra release readiness và chạy integration test**
  - Endpoints `GET /features/:id/release-check`, `POST /features/:id/release-check`, và `POST /features/:id/integration-tests` hoạt động chính xác; trả về mã HTTP 422 khi feature bị chặn phát hành với cờ `assert: true`.
  - *Bằng chứng*: `test/rel-002.test.ts` (Nghiệm thu 8).
